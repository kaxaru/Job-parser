# BI — Metabase и Power BI

## Metabase — дашборды как код

**Модули:** `bi/` — `client.py`, `config.py`, `cli.py`, `registry.py`, `dashboards/`
**UI:** `http://localhost:3000` (`demo@hh.local` / `DwhDemo2026!`)

Дашборды не собираются кликами: они описаны кодом и провижатся идемпотентно. Повторный
запуск архивирует старые карточки и пересобирает — без дублей.

### Команды

```bash
python -m bi                # = all: все дашборды
python -m bi all
python -m bi overview       # /dashboard/2
python -m bi comparison     # /dashboard/3
python -m bi cooccurrence   # /dashboard/4
python -m bi mssql          # /dashboard/5
python -m bi sources        # «Источники — сравнение порталов»
python -m bi --help
```

`NAME` — позиционный аргумент (ключ из `bi/registry.py`); флага `--dashboard` у парсера нет
и никогда не было. Пусто и `all` означают одно и то же — все пять дашбордов; этот набор
зафиксирован литеральным списком в `tests/test_cli.py::test_default_provisioning_set`,
чтобы новый класс в реестре не попадал в `python -m bi` без единого красного теста.

### Фасад Metabase

`bi/client.py::MetabaseClient` — обёртка над REST API:

```python
connect()                                        # логин, сессия
find_database(name, engine)                      # найти подключение
ensure_database(name, engine, details) -> int    # создать, если нет
run_sql(db_id, sql) -> list
create_card(name, db_id, sql, display, viz, tags) -> int
upsert_dashboard(title) -> int                   # идемпотентно
set_dashboard(d_id, dashcards, parameters)
```

`ensure_database` и `upsert_dashboard` — ключ к идемпотентности: подключения к трём
движкам и сами дашборды не дублируются между запусками.

**Fail fast со своим сообщением.** `_api` отдаёт тело ошибки 4xx/5xx СТРОКОЙ, и до
09.08.2026 она молча уезжала в `d.get(...)`/`res["id"]`: провижининг падал
`AttributeError: 'str' object has no attribute 'get'` и `TypeError: string indices must be
integers`, не называя ни статуса, ни ответа Metabase. Теперь статус проверяют все методы,
включая `find_database`/`ensure_database` и `upsert_dashboard`, и сообщение называет
виновника: `database list failed: <st> <body>`, `database '<name>' failed: …`,
`dashboard list failed: …`, `dashboard '<title>' failed: …`, `card '<name>' failed: …`.

Два уточнения того же захода: `202` (асинхронное создание) считается успехом наравне
с `200` — так же, как у `create_card`; а недоступность `/api/session/properties` больше
не роняет `connect`, а деградирует в обычный логин — инстанс может быть уже настроен,
и об ошибке логина скажет сам логин.

### Реестр дашбордов

`bi/registry.py` — то же решение, что и в ETL:

```python
REGISTRY: dict[str, type[Dashboard]] = {
    cls.key: cls for cls in (
        OverviewDashboard, ComparisonDashboard, CooccurrenceDashboard, MssqlOverviewDashboard,
        SourceComparisonDashboard,
    )
}
```

Добавить дашборд = добавить класс в кортеж. Ключ CLI берётся из атрибута самого класса.

`dashboards/base.py::Dashboard` — `Protocol` с `key`, `title` и `build(client)`.
Тип реестра `dict[str, type[Dashboard]]` даёт статическую проверку соответствия,
рантайм-проверку — тест.

Хелперы разметки там же: `layout()` раскладывает карточки по сетке, `bar()` собирает
описание столбчатой визуализации, `text_tag()` — параметр-фильтр.

### Словарь подписей

Подпись карточки — контракт с человеком, который видит только график, поэтому она обязана
называть, что метрика СЧИТАЕТ: единицу измерения и знаменатель. Обе формулировки живут
константами в `dashboards/base.py`, чтобы одно понятие звучало одинаково на всех дашбордах:

- **`REMOTE_LIKE` = «Удалённо или гибрид»** — витрины считают удалёнку по `is_remote`,
  а это коды `remote` + `flexible` (`etl/domain.py::REMOTE_LIKE_CODES`, зеркало
  `Schedule.is_remote_like` родителя). Прежняя подпись «Удалённые вакансии» была неправдой
  для всей категории `flexible` — тот же класс дефекта, что «Автобан %» с двумя
  знаменателями у родителя
- **`RUB` = « · ₽ (пересчёт по курсу)»** — единица измерения В ПОДПИСИ, а не только
  в имени колонки: человек, открывший дашборд, видит заголовок и столбики, а не SQL.
  С 09.08.2026 витрины отдают рублёвый эквивалент (`*_rub`, конверсия делается один раз
  в домене по суточному кешу курсов), поэтому суммы наконец сравнимы между источниками
  и движками
- **`MIXED_CURRENCY` = « · валюта портала (суммы не сравнимы)»** — маркер для карточек,
  считающих по СЫРЫМ суммам. Сейчас таких не осталось; константа держится как явное
  предупреждение: заводить новую карточку с ней не надо, надо брать `*_rub`. Без пометки
  график читался как «hh платит кратно меньше himalayas», хотя это рубли против долларов,
  то есть сравнивались единицы измерения, а не деньги

Ещё два правила подписи по тому же поводу: слово «вилка» из карточки источников убрано
(нижняя и верхняя границы считаются на разных множествах строк, и такой «вилки» нет ни
у одной вакансии), а «топ-12 навыков» подписан «навыков рынка — в разрезе источника»,
потому что подзапрос берёт общерыночный топ и раскладывает его по порталам, а не считает
топ-12 внутри каждого портала.

Имена карточек и заголовки дашбордов зафиксированы литералами в
`tests/test_bi_dashboards.py`: молчаливый откат подписи к «Удалённым» или пропажа пометки
о валюте делают тест красным.

### Дашборды

**`/dashboard/2` — Обзор рынка.** 7 карточек, фильтры «Город» и «Опыт». Источник —
витрины PostgreSQL.

**`/dashboard/3` — Postgres vs ClickHouse.** 14 карточек: 7 метрик × 2 движка, попарно
рядом. Смысл — показать, что одни и те же цифры получаются из разных моделей данных
(звезда против широкого факта).

**`/dashboard/4` — Со-встречаемость навыков.** Дропдаун навыка -> что ищут вместе с ним.
Self-join по мосту `core.vacancy_skills`.

**`/dashboard/5` — MS SQL / T-SQL.** Обзор на Microsoft-стеке, 7 карточек.

**Источники — сравнение порталов** (`python -m bi sources`). 5 карточек в разрезе
`source`: «Вакансий по источникам», «Средняя нижняя и верхняя граница з/п по источникам
· ₽ (пересчёт по курсу)», «Доля «Удалённо или гибрид» по источникам, %»,
«Покрытие зарплатой по источникам», «Топ-12 навыков рынка — в разрезе источника».
Читает витрину `mart.source_stats` (объём/зарплата/remote) и `core` (навыки).
Не путать с `/dashboard/3`: тот сравнивает ДВИЖКИ на одних данных, этот — ПОРТАЛЫ внутри
одного движка. Появился после подключения talanto.

Перечня порталов в заголовке НЕТ намеренно: их девять, список задаёт родитель
(`hrwork/config.py::SOURCES`), а витрина группирует по факту. До 09.08.2026 заголовок
перечислял четыре портала, пока график рисовал девять столбиков.

### Крайние случаи

- **Metabase не поднялся** — `connect()` падает; проверять `curl localhost:3000/api/health`
- **Витрины пустые** — карточки создадутся, но покажут пустоту: сначала `python -m etl all`
- **«user already exists»** — том Metabase не пуст, см. [`deployment.md`](deployment.md)
- **ClickHouse-карточки пустые** при живом Postgres — не прогонялся
  `python -m etl -t clickhouse all`
- **Переименовали `TITLE`** — заголовок и есть ключ идемпотентности `upsert_dashboard`
  (поиск идёт по имени), поэтому первый прогон после переименования создаёт НОВЫЙ дашборд,
  а старый остаётся висеть со своими карточками. Так было 09.08.2026 с «Источники — hh vs
  hirify vs talanto vs getmatch»: старый дашборд архивируется руками, автоматики для этого
  нет и не будет — угадывать, какой из двух похожих дашбордов лишний, скрипт не вправе
- **Одинаковые `title` у двух дашбордов** — второй `build` найдёт по имени первый и
  заархивирует его карточки. Уникальность заголовков закреплена тестом
  (`tests/test_cli.py::test_dashboard_titles_are_unique`)

### Как метрики уехали в рубли (09.08.2026)

Схемы трёх движков переименовали зарплатные метрики витрин в `_rub`
(`avg_salary_min_rub`, `avg_salary_max_rub`, `with_salary_rub`; в ClickHouse —
`avg_min_rub`/`avg_max_rub`), а SQL карточек за ними не пошёл, и шесть карточек несколько
часов селектили имена, которых в витринах больше нет. На живом Metabase они вернули бы
«колонки нет».

Показательно, ЧЕМ это поймали. Не тестами: страж `test_bi_dashboards.py` проверяет ПОДПИСИ,
а SQL карточек исполняется только против живой БД, которой в юнит-прогоне нет. Расхождение
заметил агент, писавший эту доку: он отказался записать требование «имена метрик сменились
на `*_rub`», потому что `grep -rn '_rub' bi/` не дал ни одного совпадения. Отказ записать
непроверенное утверждение оказался полезнее самой записи.

Пробел закрыт статическим стражем
`test_bi_dashboards.py::test_every_salary_column_a_card_selects_exists_in_some_mart`:
каждое зарплатное имя, встреченное в модуле дашборда, обязано существовать хотя бы в одной
`schema.sql`. БД для этого не нужна.

Правка здесь ПАРНАЯ и должна такой оставаться: имя колонки в SQL — и сразу подпись.
На рублёвых метриках `MIXED_CURRENCY` стал бы неправдой, поэтому единицу называет `RUB`.
Медиан витрины больше не считают: перцентиль по смешанным валютам смысла не имел, а в T-SQL
`percentile_cont` существует только оконной функцией — карточка показывает средние
по множеству строк с известной рублёвой вилкой.

## Power BI — вне Docker

**Инструкция:** `powerbi/README.md`

Power BI Desktop — Windows-приложение, контейнеризовать нельзя, и в этом стеке оно
**не установлено**. В репозитории лежит только подготовка: как поставить Desktop,
подключиться к `hh-mssql`, и готовые DAX-меры (`CALCULATE`, `DIVIDE`, `MEDIAN`).

Сам `.pbix` собирается в Desktop вручную. Источник — звезда `core` в MS SQL, та же,
что питает дашборд `/dashboard/5`.

## Две ниши BI на одном проекте

Разделение намеренное и стоит того, чтобы его понимать:

**Metabase** — аналитика данных: категориальные срезы, сравнение движков,
со-встречаемость навыков. Вопрос «что на рынке».

**Grafana** — операционный взгляд: time-series метрики прогонов Airflow и логи из Loki.
Вопрос «жив ли пайплайн». См. [`observability.md`](observability.md).

```bash
python -m bi all
python -m pytest tests/test_bi_client.py tests/test_bi_dashboards.py -q
```

Ожидаемо: дашборды доступны по `/dashboard/2` … `/dashboard/5` + «Источники — сравнение
порталов», карточки не пустые; повторный `python -m bi all` не создаёт дублей.
Тесты — 27 зелёных: фасад на замоканном HTTP и подписи/заголовки всех пяти дашбордов
на фейковом фасаде.
