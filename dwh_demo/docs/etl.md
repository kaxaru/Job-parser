# ETL — конвейер

**Модули:** `etl/` — `domain.py`, `rates.py`, `source.py`, `pipeline.py`, `config.py`, `cli.py`.

## Назначение

Прочитать JSON парсера, привести к типизированной модели, разложить по хранилищам.
Extract и transform выполняются **один раз**, load — в каждый инжектированный бэкенд.

## Домен — `domain.py`

Чистый слой: ни БД, ни драйверов. Единственный ввод-вывод спрятан за портом — курсы валют
приходят в `Vacancy.from_raw` аргументом `fx`, а достаёт их с диска адаптер `rates.py`.
Переиспользуется всеми адаптерами и тестируется без контейнеров.

**`Vacancy`** — frozen dataclass, нейтральное представление, общий контракт для всех
хранилищ; 17 полей:

```python
id: str                        # неймспейс по источникам (hirify_733072, himalayas_<слаг>) — не int
source: str                    # портал из служебного поля _source; реестр порталов ведёт родитель
name: str
city: str | None               # подпись ЛОКАЦИИ портала: «Москва», «United States»
employer: str | None
salary_min / salary_max: float | None           # в валюте портала — усреднять нельзя
salary_min_rub / salary_max_rub: float | None   # то же в рублях по курсу — усреднять можно только это
salary_currency: str | None    # канонический код: RUR -> RUB, BYR -> BYN, USDT -> USD
salary_gross: bool | None
experience: str | None         # уже человекочитаемо: «1–3 года»
schedule: str | None           # «Офис» | «Удалённо» | «Гибрид»
is_remote: bool                # ФОРМАТ работы: код remote или flexible
remote_mentioned: bool         # слово «удалённо» в тексте — отдельное понятие, не формат
url: str | None
skills: tuple[str, ...]
```

**`None` у необязательного поля означает «портал этого не сказал»** — не ноль, не пустую
строку и не «False». Пустая строка внешнего источника приводится к `None` здесь, один раз,
а не гейтами в SQL каждого движка: гейт `WHERE employer_name IS NOT NULL` пустую строку
пропускал, и в измерении заводился безымянный работодатель, к которому джойнилась каждая
седьмая вакансия. Отдельно про рубли: `salary_*_rub = None` — это «курса нет», и такая
вакансия **выпадает** из зарплатного среза, а не приезжает в него нулём (см. `rates.py`).

### Чего в контракте больше нет (09.08.2026)

- **`query`** («из какого поискового запроса пришла вакансия») — родитель это поле больше
  не пишет: перепись ключей по всем 109 597 записям кеша даёт 19 имён, `_query` среди них
  нет ни разу. Колонка, гарантированно равная NULL во всех трёх хранилищах, — худшее, что
  может быть на демо-стенде: она обещает срез, которого не существует. Колонка убрана
  и из трёх схем (`ALTER TABLE ... DROP COLUMN IF EXISTS query` — на поднятом томе
  `CREATE TABLE IF NOT EXISTS` её бы не убрал никогда). Дедуп по id при этом остался,
  но обоснование у него теперь другое — см. «Дедуп и отбраковка»
- **фолбэк `city` на `_city`** — того же происхождения: ключа `_city` в сырых записях тоже
  нет ни у одной

### Контракт `Vacancy.from_raw`

Вход — сырая запись парсера, выход — типизированная вакансия:

```python
>>> Vacancy.from_raw({
...     "id": "135125416",
...     "name": "Python-разработчик",
...     "area": {"id": "1", "name": "Москва"},
...     "salary": {"from": 150000, "to": None, "currency": "RUR", "gross": False},
...     "experience": {"id": "noExperience"},
...     "schedule": {"id": "fullDay"},
...     "snippet": {"requirement": "Опыт с Python, Docker и PostgreSQL"},
...     "employer": {"name": "НПП МетаСофт Про"},
...     "alternate_url": "https://hh.ru/vacancy/135125416",
... }, fx={"USD": 1.0, "RUB": 90.0})
Vacancy(id='135125416', source='hh', name='Python-разработчик', city='Москва',
        employer='НПП МетаСофт Про', salary_min=150000, salary_max=None,
        salary_min_rub=150000.0, salary_max_rub=None,
        salary_currency='RUB', salary_gross=False,
        experience='Без опыта', schedule='Офис', is_remote=False,
        remote_mentioned=False, url='https://hh.ru/vacancy/135125416',
        skills=('Python', 'PostgreSQL', 'Docker'))
```

Что произошло, и это видно только на паре вход/выход:

- **`id` -> `str`** — основной проект неймспейсит id по источникам (`hirify_733072`,
  `talanto_<uuid>`), а himalayas и arbeitnow — слагом вакансии, поэтому `int()` больше
  неприменим (ронял 2/3 записей в except). Ключи хранилищ — TEXT/String/NVARCHAR(200)
- **`source`** — портал из служебного поля `_source`; дефолт `hh` для legacy-срезов.
  Перечень порталов задаёт родитель (`hrwork/config.py::SOURCES`, сейчас девять),
  домен его не хардкодит и не ограничивает — новый портал доезжает до витрин сам
- **коды нормализованы**: `noExperience` -> «Без опыта», `fullDay` -> «Офис»
  (справочники `EXPERIENCE`, `SCHEDULE`). Подписи графика взяты **дословно** из домена
  родителя (`hrwork/domain/schedule.py::Schedule.label`): та же вакансия обязана
  называться одинаково в ленте и в Metabase, а прежняя подпись «Гибкий график» прятала
  от аналитика, что эти 16 935 вакансий — гибрид, то есть ровно та категория, из-за
  трактовки которой расходились доли удалёнки. Мёртвые коды `shift` и `flyInFlyOut`
  из справочника убраны: домен родителя их не производит (в `Schedule` три члена).
  Неизвестный **непустой** код по-прежнему проходит как есть, а пустой -> `None`
  (иначе защита витрин `coalesce(..., 'не указан')` не срабатывала никогда, и 20 650
  вакансий уходили в бакет с пустой подписью)
- **`salary_currency` канонизируется** — `RUR` -> `RUB`, `BYR` -> `BYN`, `USDT` -> `USD`
  (`rates.py::CURRENCY_ALIAS`, дословная копия родителя); пустая валюта -> `None`
- **`salary_*_rub`** — та же вилка по курсу из кеша; считается **один раз здесь**,
  витрины трёх движков только усредняют готовые рубли и ничего не конвертируют
- **`skills`** — стек берётся из кеша родителя (`_techs`), если сигнатура его словаря
  (`_dv`) совпала с пином `PARENT_DETECT_SIG`; поверх кеша всегда добавляются
  аналитические теги стенда (`ETL_SKILL_PATTERNS`, 18 штук: SQL, ETL, Airflow, dbt,
  Power BI, …) — у родителя их нет. Нет валидного кеша -> считаем сами всеми 37 regex
  (19 общих + 18 аналитических). Кеш в приоритете не ради скорости: пока стенд считал стек
  своим словарём, витрина «спрос на технологии» отвечала не на тот вопрос, что лента,
  и одну вакансию нельзя было сверить между ними. Возвращается кортеж, а не список:
  `Vacancy` frozen
- **`is_remote`** — `schedule` в `REMOTE_LIKE_CODES` (`remote` + `flexible`), и больше
  ничего. Это дословная копия ответа родителя (`Schedule.is_remote_like` = REMOTE + HYBRID),
  и до 09.08.2026 у стенда был свой, третий ответ («код `remote` ИЛИ маркер в тексте»):
  гибрид не считался удалёнкой, зато офисная вакансия со словом «удалённо» в описании
  считалась, и доля удалёнки в витринах расходилась с отчётами родителя на одной и той же
  выборке
- **`remote_mentioned`** — те самые текстовые маркеры («удалённ», «remote», «из любой
  точки», …), вынесенные в отдельное поле. Это признак ТЕКСТА, а не формата работы;
  в аналитический срез «доля удалёнки» он не входит, но остаётся в хранилищах для запросов
  вида «сколько офисных вакансий упоминают удалёнку»
- **`city`** берётся из `area.name`, режется до `CITY_MAX = 200` code points
  (talanto шлёт списки стран до ~2400 симв.); пусто и сентинел родителя `Remote` -> `None`.
  «Remote» — не город: до 09.08.2026 он шёл третьей строкой топа «городов» (12 177 записей),
  и в той же строке считалась `remote_share_pct` — «доля удалёнки в городе Remote».
  Факт удалёнки при этом не теряется, его несут `is_remote`/`schedule`

**`strip_html`** — снимает теги и HTML-сущности (`html.unescape`) перед разметкой навыков,
иначе разметка ловила бы совпадения внутри атрибутов, а в тексте оставались бы `&quot;`.

## Курсы валют — `rates.py`

Адаптер порта «курсы»: читает суточный кеш родителя `data/fx_rates.json` (путь —
`FX_FILE`, дефолт `etl/config.py::FX_DEFAULT`). **В сеть не ходит.** Причина не в лени:
прогон витрин не должен зависеть от доступности внешнего API и не должен молча менять
цифры между двумя запусками — файл обновляет родитель
(`hrwork/infrastructure/net/rates.py::get_rates`, TTL 24 ч), стенд его только читает.

`load_rates()` читает файл **один раз на процесс**: если бы он перечитывался, обновление
кеша посреди прогона дало бы разным вакансиям разные курсы, и три хранилища разошлись бы
в цифрах на одном входе.

Курсы — чужие данные, поэтому деградация мягкая: нет файла, битый JSON, нет ключа `rates`
-> пустой словарь и предупреждение `[etl] FX: …` в stdout. Прогон продолжается, рублёвые
колонки становятся NULL.

**Контракт `to_rub`: нет суммы, валюты или курса -> `None`.** Вакансия выпадает
из зарплатного среза, а не приезжает в него нулём — ровно так поступает `analyzer.py`
родителя. Пустая валюта тоже даёт `None`, а не рубли: допущение «HH по умолчанию рублёвый»
родитель отдельно чинил 08.08.2026 — оно верно для hh и катастрофично для восьми остальных
порталов (вилка $10 000 весила 10 000 ₽ и пряталась любым фильтром).

Путь к кешу инжектируется, а не читается изнутри: `Pipeline(source, warehouses, fx_file=…)`,
`build_pipeline` берёт его из `Settings.fx_file`. В контейнере Airflow он задан явно
(`FX_FILE=/opt/airflow/data/fx_rates.json`), потому что дефолт считается от каталога
пакета `etl/` и внутри контейнера указывал бы не туда.

## Источник — `source.py`

`JsonSource(path).read() -> list[dict]`. Один источник, но контракт позволяет добавить
другие (API, БД) не трогая конвейер.

## Конвейер — `pipeline.py`

```python
Pipeline(source, warehouses, fx_file=None)
  .prepare()          -> list[Vacancy]   extract + transform, кэшируется
  .init_schema()                          по всем хранилищам
  .load(force=False)                      по всем хранилищам + сверка
  .run(steps, force=False)                steps: пусто | ["all"] | ["init"] | ["load"]
```

**`build_pipeline(targets, cfg)`** — фабрика: собирает источник, путь к курсам и адаптеры
выбранных бэкендов из `REGISTRY`.

### Дедуп и отбраковка в `prepare`

Отбраковка считается **по причинам**: три молчаливых `continue` с одним итогом «стало
меньше» не дают отличить сломавшийся разбор от выросшей доли дублей.

```python
if not isinstance(r, dict):   broken += 1; continue   # элемент не объект — тоже брак
if not r.get("id"):           no_id  += 1; continue   # запись без id
try:    v = Vacancy.from_raw(r, fx=fx)
except (AttributeError, KeyError, ValueError, TypeError): broken += 1; continue
if v.id in seen:              dup    += 1; continue   # дубль
```

`AttributeError` в кортеже — тот же класс «в чужом JSON не тот тип» (`salary` строкой
вместо объекта): раньше он ронял **весь** прогон на одной записи.

Дедуп по id — защита **конвейера**, а не следствие поискового запроса: поля `_query`
больше нет, но кеш родителя копится несколькими прогонами по девяти порталам, и повтор id
**уронил бы** PRIMARY KEY в PostgreSQL и MS SQL, а в ClickHouse (MergeTree, ключ
не уникален) молча задвоил бы счётчики витрин.

Битые записи пропускаются молча, а не роняют прогон: источник внешний, одна кривая
запись из десяти тысяч не повод терять загрузку. Но молчание ограничено гейтом ниже.

### Санити-гейты и сверка

Загрузка **полная**: каждый адаптер сначала чистит факт, потом заливает срез целиком.
Поэтому деградированный вход здесь так же опасен, как деградированный сбор у родителя
(`hh.py collect`): затерев факт огрызком, вчерашние данные не вернуть. Отсюда три
механизма, все — с порогами-константами модуля (это политика конвейера, одинаковая
на всех стендах, а не параметр окружения):

- **Гейт брака** (`_check_broken_share`, `MAX_BROKEN_RATIO = 1 %`, работает при входе
  от `SANITY_MIN_ROWS = 500` записей). `Vacancy.from_raw` — наш код, и массовое исключение
  в нём означает смену формата поля у родителя, то есть нашу поломку. Раньше такой дрейф
  давал ноль записей и зелёный прогон, потому что `except` стоит вокруг каждой записи
- **Гейт перезалива** (`_reject_degraded`, `LOAD_MIN_RATIO = 50 %`, тот же порог
  в 500 строк). Новый срез сравнивается с тем, что **уже лежит в факте** (`Warehouse.count`),
  и просадка больше чем вдвое отменяет загрузку во **все** хранилища. Проверяются все
  адаптеры до загрузки первого — иначе первый успел бы затереть свой факт раньше, чем
  гейт скажет «нет». Хранилище без схемы (`load` без `init`) гейт пропускает: он не должен
  быть строже самой загрузки. Обход — осознанный, флагом `--force`
- **Сверка** (`_verify`). Главная проверка проекта считается числом, а не человеческим
  глазом по трём строкам stdout: `Warehouse.load` обязан вернуть число строк **в факте**,
  прочитанное из хранилища, и оно сверяется с результатом `prepare` по каждому движку.
  Расхождение роняет прогон и **называет отставший движок**

Fan-out целиком **не атомарен**: падение на втором адаптере оставит первый с новым срезом,
третий — со вчерашним. Повтор безопасен и обязателен (загрузка идемпотентна, это полная
замена факта), а о неполном результате оператор узнаёт строкой `[etl] ERROR` и падением
прогона, а не расхождением цифр на дашборде.

**Наблюдаемость.** Аварийные строки идут в **stderr** с маркером `[etl] ERROR` —
по этой подстроке строится алерт в Loki и по ней же видно поломку в эксплуатации.
Обычный `log` пишет в stdout без уровня, и строка `[etl] [postgres] loaded: 0` там
неотличима от успеха. Второй сигнал — счётчики `no_id/broken/dup` в строке `prepare`:
их рост виден до того, как гейт сработает.

**Кэширование `prepare`.** Результат считается один раз и переиспользуется всеми
хранилищами. Если бы каждый адаптер парсил сам, три движка могли бы разойтись в данных
при одинаковом входе — и сравнение потеряло бы смысл. Курсы валют читаются там же, один
раз, и передаются в домен явно.

## CLI — `cli.py`

```bash
python -m etl                      # = all: init схем + load во все бэкенды
python -m etl all
python -m etl init                 # только схемы (идемпотентно)
python -m etl load                 # только загрузка

python -m etl -t postgres all      # только Postgres
python -m etl -t clickhouse load
python -m etl -t postgres -t mssql init    # несколько — флаг повторяется
python -m etl load --force         # 🔴 грузить вопреки санити-гейту перезалива
python -m etl --help
```

Ожидаемый вывод:

```
[etl] [postgres] schema ready
[etl] [clickhouse] schema ready
[etl] [mssql] schema ready
[etl] prepare: 92730 вакансий (extract+transform); пропущено: no_id=0 broken=0 dup=16867; FX: N курсов, вилка в рублях у M
[etl] [postgres] loaded: 92730
[etl] [clickhouse] loaded: 92730
[etl] [mssql] loaded: 92730
[etl] verify: prepare=92730, в факте {'postgres': 92730, 'clickhouse': 92730, 'mssql': 92730}
```

`92730 + dup 16867` = 109 597 записей кеша: почти каждая шестая приходит повторно.
`N` — сколько курсов прочитано из кеша (ноль -> рублёвые колонки будут пустыми, прогон
при этом не падает), `M` — у скольких вакансий получилась хотя бы одна рублёвая граница.
Средние в витринах считаются по более узкому множеству — где известны **обе**
(`with_salary_rub`, см. [warehouses.md](warehouses.md)).

Совпадение чисел по всем бэкендам — главная проверка согласованности адаптеров, и с
09.08.2026 её делает сама последняя строка, а не читатель.

### Две тонкости argparse, зафиксированные в коде

**`action="append"` вместо `nargs="+"`** для `--target`: иначе опция жадно съедает
позиционный `STEP`, и `-t postgres load` ломается.

**Валидация шага через `type`, а не `choices`**: связка `choices` + `nargs="*"` в argparse
валидирует пустой список против `choices` и падает на пустом вводе (bpo-9625).

## Крайние случаи

- **Пустой список шагов** -> трактуется как `all` (`Pipeline.run`)
- **Запись без `id`** -> пропуск, счётчик `no_id`
- **Битая запись** (в т.ч. не-объект вместо записи) -> пропуск, счётчик `broken`
- **Битых больше 1 %** (при входе от 500 записей) -> прогон **падает**, хранилища
  не тронуты: это не брак источника, а смена формата у родителя
- **Пустая строка из внешнего источника** (работодатель, город, опыт, график, валюта,
  url) -> `None`
- **Неизвестный непустой код опыта/графика** -> проходит как есть
- **`prepare` вернул 0 вакансий** -> прогон **падает** (`нечего грузить`), хранилища
  не тронуты: пусто — это не деградация источника, а отсутствие входа, и молча обнулять
  три хранилища нельзя
- **Вход просел больше чем вдвое** относительно факта (при факте от 500 строк) ->
  перезалив отменён во всех хранилищах, данные сохранены; повтор при реальном спаде рынка —
  `--force`
- **Нет кеша курсов** (или в нём нет нужной валюты) -> `salary_*_rub` пустые,
  предупреждение `[etl] FX: …`, прогон продолжается; вакансия выпадает из зарплатного среза
- **Нет файла данных** -> `FileNotFoundError` из `JsonSource.read`, прогон падает —
  это не деградация, а отсутствие входа

## Осознанные компромиссы

Каждый прокомментирован на месте в коде; здесь — чтобы следующий аудит их не «починил».

- **Константы родителя скопированы, а не импортированы** (`REMOTE_LIKE_CODES`,
  `REMOTE_MARKERS`, `REMOTE_CITY`, `CURRENCY_ALIAS`, паттерны стека): `etl/` монтируется
  в контейнер Airflow **без пакета `hrwork`**, и импорт родителя уронил бы DAG на старте.
  От расхождения копий защищают страж-тесты в `tests/test_domain.py`, читающие исходник
  родителя
- **`PARENT_DETECT_SIG` — пин хеша, а не вычисление**: посчитать сигнатуру можно только
  по `hrwork.config.TECH_PATTERNS`, которого в контейнере нет. Протухание пина ловит
  страж-тест, а деградация мягкая: не совпало -> считаем стек сами
- **Фолбэк-словарь стека — подмножество**: 19 тегов из 55 родительских. Полный словарь
  не копируем: на реальном срезе кеш валиден у всех записей, а лишняя копия данных живёт
  только затем, чтобы разойтись с оригиналом
- **Экономии на `strip_html` нет**: текст всё равно нужен аналитическим тегам стенда,
  поэтому при валидном кеше экономятся только 19 regex из 37, а не разбор описания
- **Ленивый `load_rates()` внутри домена**: конвейер прокидывает курсы явно
  (`from_raw(rec, fx=fx)`), но дефолт `fx=None` оставлен для прямых вызовов (тесты, REPL).
  Это единственное место, где доменный модуль умеет сходить на диск сам
