# RFC-002: LLM-переформулировка одобренного факта под вопрос (etap 2, human-gated)

> Формат RFC: боевой путь откликов + внешний платный LLM с генерацией текста в чат.
> Ссылки на код — по имени символа. Итог ревью: автономный вариант отвергнут, финал —
> **human-gated** (изменённая формулировка не уходит без просмотра человеком).

**Статус:** Implemented (2026-07-21) · **Связано:** `chat.md`, `security.md`, `config.md`, RFC etap-1 (intent)

## Context / Motivation

`chat_answer.py::suggest` отдаёт факт из `resume_profile.json` **дословно** (шаблон `_PHRASES` +
сырой free-text). Когда бот формулирует вопрос иначе, ответ звучит канцелярски. etap-1 научил
LLM **выбирать верный факт** (метка intent); etap-2 — дать LLM **переформулировать выбранный
факт** под вопрос. Ревью показало: полностью автономно это лексикой не защитить (перестановка
клауз/вставка отрицания врут рекрутёру, проходя валидатор), поэтому etap-2 — **ассистент
фразировки под контролем человека**, а не автономный отправитель.

## Goals / Non-Goals

- **Goal:** переформулировать одобренный факт под вопрос; результат показывается человеку `[y/N]`.
- **Goal:** изменённый текст НЕ уходит без подтверждения; **крон шлёт источник дословно** (0 регресса).
- **Goal:** гарантия «не выдумывать» — валидатором грунтовки (код), не промптом.
- **Non-Goal:** LLM не выбирает факт и не отправляет автономно изменённый текст.
- **Non-Goal:** валидатор C0–C5 НЕ гарантирует «нет ложных фактов» — только «нет НОВО-токенных»;
  перестановку клауз/семантику держит человек-гейт.
- **Non-Goal:** не трогаем `salary_*`/`place_*`/`confirm`/`has_exp_no`; не в крон; не стеммим (RU-yield низкий, принято).

## Solution — слой `application`, human-gated

Модуль `chat_rephrase.py`. Встраивание — в `chat_reply.py::run`, пост-`_plan` map (`propose`/`_plan`/
тестовые моки не тронуты, `propose` без сети).

```
suggest -> ans{text,rule,lang} -> _plan -> (sendable, manual)
run: для p in sendable, если use_rephrase И eligible(p.rule):
   cand = rephrase_answer(...)               # источник при любом сбое/reject
   cand == p.text        -> авто (как сегодня)
   cand != p.text        -> _rephrase_consent(p, cand):
        tty + y           -> dataclasses.replace(p, text=cand)
        tty + n / крон    -> источник дословно
```

**Валидатор `_grounded(source, candidate, lang)`** (первый рубеж): NFKC + схлопывание разделителя
тысяч + lower; C0 echo/empty, C1 длина, C2 язык (`detect_lang`), **C3 token-superset** (значимые
токены кандидата ⊆ токены источника ∪ `_FUNC[lang]` — числа/тех/кириллица/прописью), **C4 отрицания
== (строгое равенство)**, C5 перекрытие ≥0.4. Order-blind: перестановку клауз НЕ ловит (это человек).

**C3 послабление (по запросу владельца, после demo с RU-yield≈0):** русская МОРФОЛОГИЯ слова
источника (работал→работаю, опыт→опыта) допускается по общему корню (`_same_stem`: префикс ≥4 и
≥70% длины). Строго остаются цифры/латиница/технологии/числительные-прописью (`_extra_all_stemmed`).
Порог 0.7 отсекает разные слова с общим корнем (работал/работник). Осознанный компромисс: критик
советовал НЕ стеммить в v1 (риск false-accept); принято, т.к. цифры/тех строги, а остаточные
кор-коллизии по кириллице страхует человек-гейт (крон шлёт источник).

**Whitelist `eligible`** — строго default-DENY: `years/frontend/stack_list/has_exp_yes/has_exp_past/
format/english/education/citizenship` + `practice_*`. Всё прочее (в т.ч. новое правило) — не eligible.

## Alternatives

- **Автономный (без человека)** — отвергнут РЕВЬЮ: перестановка клауз + вставка отрицания проходят
  лексический валидатор. Human-gate — прямая рекомендация критик-агента (M-3).
- **B** LLM из всего профиля — выдумывает, сливает профиль. **C** статус-кво — дефолт (флаг OFF).
- **D** переформулировать salary/place — числа/sensitive. **E** раздельные число/латиница — пропускает
  новую кириллицу. **F** Anthropic напрямую — OpenRouter-обёртка уже есть. **G** substring-only
  валидатор — автономно-безопасен, но reshape = префикс; отложен на будущее.

## Risks (ситуация -> фолбэк)

- Перестановка клауз / семантика / number-swap / hedge-drop (валидатор НЕ ловит) -> **человек-гейт**;
  крон -> источник.
- Вставка/потеря отрицания -> C4 `==` + `has_exp_no` исключён + отрицания вне `_FUNC`.
- Новый факт (число/тех) -> C3. Prompt injection -> вопрос=данные + вывод фильтруется + человек видит.
- Неизвестное правило -> default-DENY. `REPHRASE_LLM=off` -> truthy-set -> OFF. markdown/URL -> пост-фильтр.
- LLM недоступна/нет ключа/выключено -> источник. Приватность: один одобренный факт + вопрос наружу.
- 474→524 теста: флаг OFF -> rephrase не зовётся -> зелёные.

## Migration / Rollback

Ничего не пере-собирать; деплой «спящим» (флаг OFF). Включение: `REPHRASE_LLM=1` + `--rephrase`.
Откат: `REPHRASE_LLM=` / убрать `--rephrase` -> мгновенно источник дословно.

## Ревью (Codex недоступен — независимый критик-агент, протокол `upgrade.md`)

Цикл 1 → **NEEDS_REVISION**. 2-й цикл не запускался: финал реализует прямую рекомендацию критика
M-3 (human-gate) — консенсус достигнут принятием его предложения. **Принято (изменило дизайн):**
C-1 перестановка клауз проходит лексику → фича стала human-gated; C-2 вставка отрицания → C4 `==` +
отрицания вне `_FUNC`; M-3 → `_rephrase_consent`, без tty → источник; M-4 RU risk-skew → человек-гейт
снимает; m-5 eligible → default-DENY; m-6 env → явный truthy-set; m-7 → пост-фильтр markdown/URL;
m-8 → проводка в `run` (нулевая правка моков). Развилка масштаба вынесена пользователю → **Human-gated**.
