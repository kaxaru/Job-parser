# Шаблон спецификации — инстанцирование для hr_work

Спека — не проза, а **контракт с гейтами**. Пишется ДО кода и отвечает на вопрос «почему мы
уверены, что это сработает», а не «что примерно сделаем». Причина строгости: часть путей
необратима (`hh_apply` шлёт реальные отклики, сбор перезаписывает кеш), поэтому «сделаем и
посмотрим» недопустимо.

**Общие нормы живут не здесь.** Гейты готовности — в [`../CLAUDE.md`](../CLAUDE.md#спецификации),
правила тестов — в [`testing.md`](testing.md#главное-правило), разделы для необратимого
(Alternatives / Migration / Rollback / Политика восстановления / Наблюдаемость) — в
[`rfc-template.md`](rfc-template.md). Базовый межпроектный шаблон — `spec-template-universal.md`
уровнем выше дерева проектов.

Этот файл владеет ровно тем, что специфично для hr_work: слои, контракты VO, эталон
оформления, скелет и заполненный пример. Каждое нормативное утверждение определено в одном
месте — дублирование работает, пока норму не трогают, а в день изменения даёт дрейф.

## Что здесь своё

### Слои и владелец куска

Проект разложен на четыре слоя: `domain / application / infrastructure / presentation`.
Для каждого куска сказать, в каком слое живёт и почему. Гейт формулируется как «назван
владелец и направление зависимости», а не «назван слой».

Доменное понятие описывается Value Object'ом. `ApplyTier(IntEnum)` появился вместо `tier: int`
именно потому, что магический `0`-сентинел был пойман на этапе спеки.

**Два контракта разбора, выбрать явно:**

- **мягкий** — `from_code() -> VO | None`, дефолт применяет вызывающий (внешние данные)
- **строгий** — `from_label()` бросает исключение, fail-fast на дрейф (наши константы)

### Ключевые файлы: НОВЫЕ против ПРАВОК

Дешёвая оценка радиуса поражения: новый модуль изолирован, правка в `autoclick.py` трогает
боевой путь откликов.

```
НОВЫЙ:  hrwork/infrastructure/net/rates.py (+ data/fx_rates.json кеш)
ПРАВКИ: hrwork/presentation/views/feed.py, src/feed/{model,main}.js
```

### Контракт — реальным примером

Перечень полей выглядит понятным и скрывает ровно те ошибки, которые дорого стоят.

ПЛОХО: `GET /api/search — параметры: q, city, sal_min, limit, offset`

ХОРОШО:

```
GET /api/search?q=python&city=Москва&sal=150000&limit=20

{"query": "python", "sal_min": 150000, "total": 412, "count": 20,
 "results": [{"id": "134809303", "name": "Python Developer", "rank": 0.0607}]}
```

Разница не косметическая: в query параметр называется `sal`, а внутри — `sal_min`. По списку
полей это не видно, и фильтр молча не сработает. Ошибка реально жила в документации, пока
контракт не был выписан примером.

Брать из живой системы (`curl`, вызов `store.*`, дамп файла), перечислять **все** значения
enum-полей (`sender` — `bot | template | human`), показывать ответ при отказе и при пустом
результате, необратимые операции помечать в контракте, а не в прозе.

### Единообразие и уровни абстракции

Когда описывается больше трёх однотипных вещей (эндпоинты, источники, задачи крона) —
одинаковые разделы у каждой: читатель ищет ответ на один вопрос по всем элементам, и
сканирование одинаковых заголовков быстрее чтения прозы.

Эталон в проекте — [`api.md`](api.md): Назначение · Request · Parameters · Response ·
Status Codes · Implementation · Edge cases · Почему так.

**Уровни не смешивать.** В одном абзаце `503`, `SearchUnavailable`, Postgres и «лента
продолжает работать» — четыре разных уровня, такой абзац невозможно ни просмотреть, ни
поддерживать. Схема потока — если задействовано больше двух модулей.

### Риски — формат и живой пример

**Ситуация -> что сломается -> что делаем.** Пример: «`BYR` — старый белорусский код, в API
его нет -> конверсия даст мусор -> алиас `BYR->BYN`; если и `BYN` нет в ответе — фолбэк-курс».

Обязательный чеклист и политика восстановления — в [`rfc-template.md`](rfc-template.md).

### Осознанные компромиссы

Самый недооценённый раздел: без него следующий аудит «починит» решение, принятое специально.
В эпоху агентной разработки это основной источник регрессий — непомеченный компромисс
неотличим от небрежности.

Живой пример: таймауты и селекторы в `autoclick.py` выстраданы инцидентами и владеются кодом,
а не выводятся из намерения. Перегенерация такого модуля по спеке сотрёт знание, купленное
авариями; мост между мирами — [`errors.md`](errors.md).

### Ревью

Codex по протоколу `upgrade.md` (максимум 3 цикла, вердикт APPROVED / NEEDS_REVISION).
Модели `gpt-5.x-codex` для текущего аккаунта заблокированы — тогда раздел «Само-ревью», где
решение записано ВМЕСТЕ с отвергнутой альтернативой:

> База USD для конверсии — избегаем цепочек ошибок при кросс-курсах; round-trip тест страхует.

## Мини-пример (заполненный)

**Context.** `sync_statuses` помечает FORM-вакансии как отказ; в `feed.html` они уже
маркируются как форма (`candidates.py::APPLY_SKIP_FORMS`). Двойная маркировка — 47 записей
за 19.07.

**R1.** Вакансия-опросник не получает статус «отказ» от синка — проверяется отсутствием строк
`Отклик` по её id в логе прогона.

**Архитектура.** `form_ids: frozenset[str]` прокидывается в `pick_candidates`; решение
«пропустить» принимается в application-слое, синк о формах не знает.

**Политика восстановления.** Синк прерван на середине -> обработанные записи уже в `marks`
(пишем поштучно), повтор идемпотентен, инвариант «id из `form_ids` не помечен отказом»
держится и при частичном проходе.

**Риск.** Вакансия перестала быть формой -> id остаётся в `form_ids` навсегда. Фолбэк:
пересчёт множества при каждом сборе, не накопление.

**Верификация.** R1 -> `pytest tests/backend/application -k form` -> 3 passed ·
`test_form_vacancy_not_marked_rejected`; прогон `--apply-limit 5` -> в `logs/hr_work_*.log`
нет строк `Отклик` по id из `form_ids`. Непокрытые цели: нет.

**Не делаем.** Автозаполнение форм — отдельный трек (стал RFC-003).
