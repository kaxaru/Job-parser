# Сбор данных

**Слой:** `hrwork/infrastructure/sources/`, `net/`. Оркестрация — `hh.py:collect()`.

## Назначение

Собрать вакансии из нескольких порталов, привести к доменной модели, сохранить в кеш.
Не потерять уже собранное, если источник заблокировал.

## Границы

Входит: HTTP-доступ к источникам, ретраи, прокси, ACL источник -> `VacancyRecord`,
инкрементальный кеш описаний, санити-гейт перезаписи.

Не входит: классификация ролей и техов (это `domain/parsing.py`), хранение
(`storage/repository.py`), аналитика.

## Реестр источников

`sources/base.py` — ABC `Source` с единственным методом `async collect() -> list[VacancyRecord]`.
Реестр `_REGISTRY` + декоратор `@register_source(name)`; `get_source(name)` возвращает `None`
на неизвестное имя, а не бросает.

Добавить портал = подкласс `Source` + **строка импорта в `sources/__init__.py`** + имя в
`config.SOURCES`. Импорт обязателен: регистрация в `_REGISTRY` — side-effect декоратора, и
без строки `from . import <модуль>` класс просто не выполнится, `get_source()` вернёт `None`,
а сбор молча пройдёт мимо портала. Оркестратор `collect()` конкретных классов не знает.

Источники собираются **параллельно** (`asyncio.gather`), каждый обёрнут в `try/except` —
падение одного портала не убивает прогон (`hh.py::collect`).

## HH — HTML-скрейпинг

API `dev.hh.ru` закрыт для анонимного доступа, поэтому данные берутся из поисковой выдачи.

Endpoint: `https://hh.ru/search/vacancy?text=&area=&page=&items_on_page=`,
карточка — `https://hh.ru/vacancy/<id>`.

**Ключевой приём:** данные не парсятся из HTML-разметки, а вынимаются из встроенного JSON
`<template id="HH-Lux-InitialState">` (`sources/hh.py::_extract_state`). Разметка меняется, JSON-состояние
стабильно.

**Транспорт — curl-подпроцессы**, не aiohttp: через VPN на Windows aiohttp падал с
`WinError 64` (`sources/hh.py::HHHtmlClient`).

**Ретраи** (`_get_state`, `sources/hh.py::_get_state`): 5 попыток, бэкофф 1 с -> ×2, потолок 20 с.
Ретрай срабатывает не только на сбое curl, но и на «HTML пришёл, а state нет» — так ловится
soft-блок DDoS-Guard, который отдаёт 200 с заглушкой.

**Два этапа** (`collect_all`, `sources/hh.py::collect_all`):

1. **Поиск** — все `SEARCH_QUERIES × CITIES` параллельно; страницы внутри города
   последовательно. Лимит `MAX_PAGES=20 × PER_PAGE=100` = 2000 вакансий на город.
   Дедуп по id, затем отсев `is_hard_non_it` **по тайтлу до enrich** — экономит самый долгий этап.
2. **Enrich карточек** — батчами `CONCURRENCY × HH_ENRICH_BATCH_MULT`, пауза `PAGE_DELAY=0.25`.

Город берётся из **параметров поиска**, а не из поля `area` вакансии.

Тайминги `creationTime` / `publicationTime` есть **только в поисковой выдаче**, на карточке
их нет — отсюда двухэтапность нельзя развернуть в «сразу карточки».

`sig` = `publicationTime | creationTime` — маркер изменения: переоткрытие вакансии его бампит.

### ACL: что приходит и что получается

`sources/hh.py::_record_from_search_item` переводит внешний JSON **сразу в домен** —
промежуточного raw-dict нет.

Вход — элемент поиска из `HH-Lux-InitialState`. Ключи ниже взяты из кода маппинга,
значения — из соответствующей сохранённой записи:

```json
{
  "vacancyId": 135125416,
  "name": "Python-разработчик",
  "compensation": {"from": 150000, "to": null, "currencyCode": "RUR", "gross": false},
  "workExperience": "noExperience",
  "workFormats": [{"workFormatsElement": ["ON_SITE"]}],
  "company": {"visibleName": "НПП МетаСофт Про"},
  "creationTime": "2026-07-13T12:04:03.511+03:00",
  "publicationTime": {"$": "2026-07-19T12:04:03.511+03:00"},
  "totalResponsesCount": 432,
  "links": {"desktop": "https://hh.ru/vacancy/135125416"}
}
```

Выход — `VacancyRecord`, на диск ложится так:

```json
{
  "id": "135125416",
  "name": "Python-разработчик",
  "area": {"id": "1", "name": "Москва"},
  "salary": {"from": 150000, "to": null, "currency": "RUR", "gross": false},
  "experience": {"id": "noExperience"},
  "schedule": {"id": "fullDay"},
  "employer": {"name": "НПП МетаСофт Про"},
  "created_at": "2026-07-13T12:04:03.511+03:00",
  "published_at": "2026-07-19T12:04:03.511+03:00",
  "responses": 432,
  "_source": "hh",
  "_sig": "2026-07-19T12:04:03.511+03:00",
  "_enriched": false
}
```

Что происходит в маппинге, и это видно только на паре вход/выход:

- **Зарплата приводится к net** через `Salary(...).net()`. У этой записи источник уже отдал
  `gross: false`, поэтому сумма не изменилась; при `gross: true` она была бы умножена
  на `NET_FROM_GROSS = 0.87`. На диск в любом случае ложится net, поэтому повторное чтение
  не вычитает НДФЛ снова
- **`workFormats`** — список вложенных элементов, схлопывается в один `Schedule`
  по приоритету REMOTE > HYBRID > OFFICE
- **`company.visibleName`**, а не `name` — у HH это разные поля
- **`area` не из вакансии**, а из параметров поиска: так вакансия числится за городом,
  под которым найдена
- **`publicationTime`** приходит объектом то с ключом `$`, то с `@timestamp` — ACL
  разбирает оба
- **`_enriched: false`** — на этом этапе `techs` и `role` посчитаны только по тайтлу,
  `detect_text=name`; полный текст добавит `_rebuild_techs` на втором этапе
- Границы вилки проверяются через `is not None`, не truthiness: `from=0` валиден

## hirify — JSON-API

Endpoint `https://api.hirify.me/api/vacancies?{HIRIFY_PARAMS}&page=N`, деталь — `/{slug}`.
Публичный API, прокси не нужны, ретраи легче (4 попытки, потолок 10 с).

Пагинация Laravel-стиля: страница 1 отдаёт `last_page` на верхнем уровне, дальше 2..N
параллельно. Страховка `max_pages=2000` от кривого `last_page`.

**Нормализация периода зарплаты** — эвристика, потому что периода в JSON нет. Своей копии
правила у адаптера **больше нет**: он считает USD-серединку (`sources/hirify.py::_usd_mid`) и
ЯВНО зовёт домен — `Salary.monthly(min, max, currency, SalaryPeriod.infer(usd_mid))`.
Само правило живёт в `domain/salary.py::SalaryPeriod.infer`: `< $300` -> часовая,
`> $25 000` -> годовая, иначе месячная; пересчёт к месяцу (час × `WORK_HOURS_PER_MONTH=160`,
год / `MONTHS_PER_YEAR=12`) — `SalaryPeriod.to_monthly`, **в исходной валюте**. Пороги —
`config.py::HIRIFY_HOURLY_MAX_USD` / `HIRIFY_YEARLY_MIN_USD` (имена исторические, по первому
потребителю; действуют на все порталы).

Спорный диапазон $300–25 000 разрешается в пользу «месяц» — это осознанная неточность,
а не недосмотр.

**Три пути описания** (`sources/hirify.py::HirifySource.collect`): кеш (сеть не трогаем) · полный `/slug`
(не более `HIRIFY_ENRICH_MAX=600` за прогон, свежие в приоритете) · tldr-заглушка с
`enriched=False`, доберётся в следующий прогон. Покрытие описаниями растёт день за днём —
на 18k вакансий per-vacancy fetch за один раз непрактичен.

## talanto — JSON-API

Endpoint `https://talanto.work/api/jobs/?{TALANTO_PARAMS}&offset=N` (limit/offset,
`items`+`total`; limit=100 подтверждён), деталь — `/api/jobs/{id}` (HTML-описание + `url`
первоисточника: телеграм-канал/сайт). Публичный API, прокси не нужны. `/contacts` — только
под авторизацией, не трогаем. Без `period` — все активные (~40–50k; сайт показывает меньше,
API отдаёт шире — старые уходят в ghost-класс свежести).

Нормализация (`sources/talanto.py::_normalize`): `remote_type` -> `Schedule` (мягкий маппинг,
неизвестное -> OFFICE), `level` (junior/mid/senior/lead) -> `Experience` (неизвестное ->
None), зарплата RUB как есть (`gross` в API нет — НДФЛ не вычитаем повторно), `skills[]` в
`detect_text`. Enrich — тот же инкрементальный паттерн, что hirify (кеш по `_sig` =
`last_verified_at`, `TALANTO_ENRICH_MAX=600` за прогон), плюс `is_hard_non_it` ДО enrich —
карточки заведомо не-IT не качаются вовсе.

## getmatch — JSON-API

Endpoint `https://getmatch.ru/api/offers?sa=any&p=1&offset=N&limit=100&pa=all`
(`offers`+`meta.total`), деталь — `/api/offers/{id}`. Отвечает анонимно, прокси и куки
не нужны. Портал маленький: ~740 активных вакансий против 24k у hh.

**Сбор обязательно двухфазный.** В списке НЕТ грейда и полного описания: `description_html`
там всегда `null` (не обмануться именем поля), а `offer_description` — выжимка на 300–600
символов. Карточка даёт `description` (1.4–4 КБ), `seniority` и
`required_years_of_experience`. Без второй фазы вакансия осталась бы без опыта, а по нему
идёт отбор под отклик.

Нормализация (`sources/getmatch.py::_normalize`): `seniority` -> `Experience`
(`Experience.from_getmatch`; грейд приоритетнее числа лет — словарь тот же, что у hirify,
и «senior» с разных порталов обязан попасть в одну корзину), `location_items[].format`
(office/hybrid/remote/relocation_company) -> `Schedule` (`relocation_company` = офис, это
переезд ради работы на месте), `salary_taxes: gross|net` приходит явно — НДФЛ считает
`Salary` VO. `skills_objects[]` идут в `detect_text`, а не в обход `_detect_techs`: точка
детекции стека одна на все источники.

Чего API не отдаёт: **счётчика откликов** (`responses=None`, как у hirify). Зарплата
скрыта примерно у 59 % карточек, `english_level` заполнен у 8 %.

Промо-блок «one day offer» (`offer_type != "vacancy"`) приезжает в КАЖДОЙ странице выдачи —
отбрасывается, иначе размножился бы по числу страниц.

## arbeitnow и himalayas — глобальные источники

Первые НЕ-русскоязычные порталы в сборе (07.08.2026): hh/hirify/talanto/getmatch закрывают
рынок РФ, эти два — удалёнку и релокацию на глобальном рынке.

Оба **однофазные**: полное `description` (HTML) приходит уже в списке, отдельная карточка
не нужна, поэтому ни кеша описаний, ни enrich-лимитов у них нет.

**arbeitnow** — `https://www.arbeitnow.com/api/job-board-api?page=N`, 100 записей на странице,
~41 страница (≈4100 вакансий). Уклон в Германию/ЕС; удалёнки мало — 224 из 4068 в замере,
остальное офис. API не отдаёт **ни вилки, ни грейда**: `job_types` содержит категории вроде
`professional / experienced`, а это не шкала junior/middle/senior, поэтому `experience=None`.
Выводить грейд из тайтла нельзя — он поедет относительно hirify/getmatch, где грейд приходит
полем. Обход останавливается на первой пустой странице; `meta.total` портал не отдаёт.

**himalayas** — `https://himalayas.app/jobs/api?limit=20&offset=N`, целиком про удалёнку.
Страница жёстко **20**: `limit` больше портал игнорирует. Выдача кончается на offset ≈97 300
(≈4870 страниц, ~50 суток вглубь), и `HIMALAYAS_MAX_PAGES = 5000` покрывает её ЦЕЛИКОМ —
обход всё равно рвётся на первой честно пустой странице, лишние итерации не тратятся.
Замер после переделки (07.08.2026): **26 027 IT-вакансий, 4813 страниц, 41.9 мин**.

Лимит смогли поднять с 2000 до 5000 потому, что источник **больше не копит сырые карточки
до `return`**. Раньше карточка тащила полный HTML описания, и на 2000 страницах процесс
занимал 731 МБ (на 4900 было бы ~1.8 ГБ при одновременном прогоне hh и talanto). Теперь
`himalayas.py::collect` нормализует и отсеивает не-IT **пачками**, в памяти остаются только
выжившие — 37 % выдачи. Та же схема потом применена в `themuse.py::collect`.

Дублей в выдаче много: 5810 из 40 000 (14.5 %). Offset-пагинация отдаёт пересекающиеся окна,
потому что выдача сортируется по дате и сдвигается между запросами. Дедуп по `guid` обязателен.

Усечение обхода **не молчит**: если цикл упёрся в `HIMALAYAS_MAX_PAGES`, а выдача не
исчерпана, в лог уходит `WARNING ... обход УПЁРСЯ В ЛИМИТ N страниц`. Именно молчание
превратило инцидент с троттлингом (ниже) в «успешный» сбор 40 % портала.

Данные там богаче: грейд (`seniority`), вилка с валютой и периодом, тип занятости и
`locationRestrictions` — список стран, из которых работодатель готов нанимать. Последнее
пишется в город: «remote» на глобальном рынке чаще всего значит «remote в пределах США», и
без этого поля лента забивается вакансиями, куда откликаться бессмысленно. Пустой список =
нанимают откуда угодно -> город `Worldwide`.

**Три ловушки himalayas, все пойманы живым прогоном, все закрыты тестами:**

1. `companyName` приходит литеральной ЗАГЛУШКОЙ — строкой `"name"` во ВСЕХ записях (как и
   `companyLogo` = `"thumbnail_url"`). Настоящее имя только в `companySlug`, оттуда и берём,
   разворачивая слаг обратно (`bright-vision-technologies` -> `Bright Vision Technologies`).
   Взять `companyName` означало бы порчу данных: ключ дедупа — пара (работодатель, тайтл),
   и одинаковый «name» у тысяч записей схлопнул бы разные компании в одну вакансию.
2. Зарплата **годовая** у 88 % записей (`salaryPeriod`: annual/hourly/monthly), а весь домен
   считает вилку месячной. Приводим доменной фабрикой `Salary.monthly` (annual / 12,
   hourly × 160 ч/мес) — адаптер только достаёт поля и переводит код периода в
   `SalaryPeriod.from_code`. Неизвестный период -> вилку не берём вовсе (`period=None` ->
   `None`): ошибка в 12 раз хуже пустого поля, и здесь инференс НЕ запрашивается — поле
   заполнено почти везде, пустое значит аномалию. `gross=False` — вычитать НДФЛ 13 %
   из зарубежной вилки нельзя, там своя налоговая система.
3. **Троттлинг, замаскированный под конец выдачи.** Примерно на 1900-м запросе подряд портал
   начинает отдавать пустой список — внешне неотличимый от «вакансии кончились». Обход
   выходил по первой пустой странице, обрывался на 40 % (встал на offset 38 900, при том что
   одиночные пробы сразу после этого отдавали данные вплоть до 95 000, и только 97 400 был
   честно пуст) и **отчитывался как успешный**: 12 043 вакансии легли в кеш под видом полного
   среза. Фикс, три части: **перепроверка пустой страницы** (`himalayas.py::_get_page` — 3
   попытки с паузами 2/4/8 с; пришли данные -> это был троттлинг, пусто после всех -> конец
   выдачи), **конкурентность 12 -> 6** (`HIMALAYAS_PAGE_CONCURRENCY`) и **пауза между пачками**
   `HIMALAYAS_BATCH_PAUSE = 0.4` с. После фикса — 26 027 вакансий, 4813 страниц, 41.9 мин
   вместо 12 043 за 8.7 мин. Дешевле подождать, чем недособрать 60 % портала.

**Не-IT отсеивается на входе** (`config.GLOBAL_SOURCES_IT_ONLY`, по умолчанию включено).
Флаг общий для **всех пяти глобальных источников** — arbeitnow, himalayas, web3, themuse,
jobicy; у профильных РФ-порталов (hh/hirify/talanto/getmatch) его нет.
Это общие job-борды, а не IT-порталы: замер дал 66 % и 63 % не-IT (ритейл, продажи, логистика,
медицина), причём доля ровная по всей глубине выдачи — «дальше мусорнее» не работает.
У профильных источников она 5–37 % (hirify 5, getmatch 9, talanto 28, hh 37), там фильтровать
нечего. Без отсева 67k посторонних записей удвоили бы кеш и откатили оптимизацию его загрузки
(67 -> 29 с), ничего не дав CRM по IT-вакансиям.

Автоотклик к обоим неприменим: Playwright-путь заточен под форму HH, здесь внешние ссылки.

## web3.career — web3/крипто-рынок

`https://web3.career/api/v1?token=…&limit=100&tag=…&show_description=true`. **Требует токена**
(`WEB3_TOKEN`, бесплатный, по email); без него источник пропускается, а не падает — анонимный
вызов редиректит на форму регистрации. Домен узкий, но интересен бэкендом и дата-инженерией в
крипто-компаниях: Coinbase, Kraken, Tether, Bitfinex, Ripple, Polymarket, Binance.

**Пагинации у API нет** — это определяет всю схему сбора. Документированы только `remote`,
`limit` (максимум 100), `country`, `tag`, `show_description`; проверены и отвергнуты `page`,
`offset`, `skip`, `start`, `p` — все пятеро возвращают ту же первую сотню. Поэтому охват
набирается **перебором тегов** (`WEB3_TAGS`): каждый отдаёт свои до ста, объединение даёт
покрытие. Сейчас в списке **40 тегов** — стек (python/backend/golang/rust/sql/postgres/…),
инфра и данные, грейдовые (junior/entry-level/intern), форматный `remote` и доменные
(blockchain/defi/solidity/evm/layer-2). Замер 07.08.2026 на прежних 17 тегах — 957 уникальных
вакансий; текущие 40 дают 1835 за 66 с.

Список тегов задан в конфиге явно, а не парсится с главной портала: разметка может измениться
в любой момент, и молча опустевший список означал бы молча опустевший сбор.

**Ловушка: `show_description=false` ОБНУЛЯЕТ выдачу.** Документированный параметр не убирает
описания, а возвращает пустой список — `tag=python` даёт 100 вакансий, он же с
`show_description=false` ноль (проверено 07.08.2026). Внешне это неотличимо от «по тегу ничего
нет», поэтому параметр не используется даже ради экономии трафика.

**Зарплата — тот же инференс периода, что у hirify, и он запрашивается ЯВНО.** `salary_unit`
заполнен примерно у 5 % записей (HOUR у 2 и YEAR у 3 из 100), при том что значения есть:
`150000-180000` без единицы. Честно отбросить такую вилку, как сделано в himalayas, значило бы
потерять 95 % вилок портала. Правило (`sources/web3career.py::_salary`): единица известна ->
`SalaryPeriod.from_code`; неизвестна -> `SalaryPeriod.infer` по величине. Своего порога у
адаптера НЕТ — общий `HIRIFY_YEARLY_MIN_USD = 25 000` из домена. Раньше здесь стояло 15 000
против 25 000 у hirify, и один и тот же вопрос имел два разных ответа (сведено 07.08.2026).

**Валюта не выдумывается.** Её нет у ~94 % записей, а на крипто-рынке платят и в USD, и в
стейблкоинах. Подстановка USD по умолчанию наврала бы рублёвой аналитике (`Salary.to_rub`
сконвертировал бы по курсу то, что валютой не является). Вилка сохраняется с `currency=None`:
величина видна в карточке, в денежные срезы запись не попадёт.

**Грейд не выводится из тегов.** В `tags` встречаются junior/entry-level/lead, но это свободные
метки работодателя вперемешку со стеком и бенефитами, а не шкала; вывод из них разъехался бы
с hirify/getmatch, где грейд приходит полем. `experience=None`.

Дублей в выдаче много — теги пересекаются по построению (одна вакансия имеет и `python`, и
`backend`, и `remote`), плюс работодатели публикуют одно и то же по многу раз (в замере 11
одинаковых «Backend Engineer - Wallets» от Tether). Дедуп по `id` обязателен, кросс-портальный
по (работодатель, тайтл) снимает остальное.

## themuse.com — комбинации фильтров вместо глубокой пагинации

`https://www.themuse.com/api/public/jobs?page=N&category=…&level=…`. Ключ не нужен. Самый
крупный из глобальных: **407 097** вакансий в общей выдаче против ~97k у himalayas и ~4k у
arbeitnow. Ценен ещё и тем, что отдаёт **грейд полем** (`levels`) — у arbeitnow и web3 его
нет вовсе, и там `experience` остаётся пустым.

Схему сбора задают два ограничения API, оба замерены 07.08.2026.

**1. Потолок пагинации — 99 страниц по 20 = 1980 записей на запрос; страница 100 отдаёт
HTTP 400.** Поэтому охват набирается **комбинациями `category × level`** (`THEMUSE_QUERIES`,
9 штук: Software Engineering / Data and Analytics / Data Science / IT × Entry Level и Mid
Level, плюс `location=Flexible / Remote`), каждая до своих 1980 — как перебор тегов у
web3.career. Серверные фильтры реально сужают выдачу: без фильтра 407k,
`category=Software Engineering` — 100 877, плюс `level=Entry Level` — 30 348, но глубже
1980 по ОДНОЙ комбинации не достать никак. Из уровней берутся только Entry и Mid: senior и
выше всё равно в чёрном списке отбора (`docs/apply.md`), тратить на них комбинации незачем.
Потолок продублирован константой
`themuse.py::PAGE_CEILING = 99` и берётся как `min(THEMUSE_MAX_PAGES, PAGE_CEILING)`:
поднять env-ручкой выше жёсткого предела портала нельзя.

**2. Сортировки по дате НЕТ.** `descending=true` порядок по свежести не даёт: на первой
странице соседствуют февраль и июль, в выдаче попадаются публикации годичной давности.
Поэтому **свежесть режется на нашей стороне** — `THEMUSE_MAX_AGE_DAYS = 60`, ровно граница
гост-вакансии в домене (`freshness.GHOST_DAYS`): старше — отклик бессмыслен, а кеш такие
записи забивают. Возраст считает домен (`freshness.age_days`), а не своя копия в адаптере:
самописный вариант падал `TypeError` на дате без таймзоны, а исключение отсюда рвёт сбор
всего источника; `parse_dt` от этого защищён и понимает ISO, «Z» и unix-секунды.

Сбор **однофазный**: `contents` (полный HTML) приходит в списке. Нормализация и отсев идут
**пачками** (`themuse.py::collect::_take`) — та же схема, что в himalayas после замера на
731 МБ: сырые карточки с полным HTML до конца обхода не копятся. Обход комбинации
останавливается на первой пустой странице.

Нормализация (`sources/themuse.py::_normalize`): id неймспейснут `themuse_<id>`;
`levels[].short_name|name` -> `Experience.from_grades` (домен, а не своя таблица);
**вилки в API нет вовсе** -> `salary=None`; город — до трёх `locations[].name` через запятую
(дальше «…»), пусто -> `Remote`; удалёнка выражена САМОЙ ЛОКАЦИЕЙ («Flexible / Remote»),
отдельного флага нет — отсюда `_is_remote` по подстроке `remote|flexible`.
Автоотклик неприменим: заявка уходит на сайт работодателя (`refs.landing_page`).

## jobicy.com — перебор индустрий

`https://jobicy.com/api/v2/remote-jobs?count=N&industry=…`. Ключ не нужен, портал целиком
про удалёнку. Профильнее arbeitnow и himalayas по формату и, как himalayas, отдаёт географию
найма отдельным полем `jobGeo` («USA», «UK», «Anywhere», «EMEA», «APAC, Australia») — без него
лента забивается вакансиями, куда откликаться бессмысленно.

**Пагинации у API нет вообще** — есть только `count` (сколько отдать за раз) с потолком 100
(`JOBICY_COUNT`, больше портал игнорирует). Поэтому охват набирается **перебором индустрий**
(`JOBICY_INDUSTRIES`, 11 значений: engineering, dev, data-science, devops-sysadmin, business,
product, design, technical-support, management, finance-legal — **и пустая строка**). Пустая
строка не опечатка: это запрос БЕЗ фильтра, общая свежая выдача, которая даёт то, что не
попало ни в одну индустрию. Конкурентность — `JOBICY_REQUEST_CONCURRENCY = 4`.

Дедуп по `id` обязателен: индустрии пересекаются (вакансия бывает и в «engineering», и в
«devops-sysadmin»), плюс запрос без фильтра возвращает часть тех же карточек.

Сбор **однофазный**: `jobDescription` (HTML) приходит в списке. Нормализация
(`sources/jobicy.py::_normalize`): id неймспейснут `jobicy_<id>`; `jobLevel` — строка через
запятую («Entry-Level, Junior»), адаптер лишь режет её по запятой, а что грейды означают,
решает домен (`Experience.from_grades`, берётся младший); `schedule` **всегда** `REMOTE`;
`jobGeo` -> город, пусто -> `Remote`; **вилки нет** (поля пустые у всех записей) ->
`salary=None`. Автоотклик неприменим: заявка уходит на сайт работодателя.

## Дедуп между порталами

`domain/dedup.py::dedup_cross_source` — после слияния источников и **строго после
санити-гейта**: гейт меряет здоровье ИСТОЧНИКА («портал отдал привычный объём?»), и
прореженные счётчики он принял бы за просадку портала, заблокировав запись кеша.

Ключ — **(работодатель, тайтл)**, оба нормализованные: снимаются орг-формы (ООО/ЗАО/ИП),
уточнения в скобках, пунктуация, ё->е. Грейд в тайтле остаётся — «Junior Python» и
«Senior Python» у одного работодателя разные вакансии. Пустой работодатель или тайтл ->
вакансия в дедупе не участвует (иначе склеились бы разные компании под пустым ключом).

**Города в ключе нет, и это осознанно.** Замер 01.08.2026 по кешу 87 118 записей: 3663
кросс-портальные группы, из них 894 с формально «разными» городами — но это в основном одна
и та же вакансия с разной гранулярностью локации (hh: «Москва», talanto: «Химки»,
«Зеленоград», «рабочий посёлок Быково»). Город в ключе заблокировал бы эти склейки.

Компромисс: две РАЗНЫЕ вакансии одного работодателя в разных городах схлопнутся, и одна
потеряется. Цена принята — победитель выбирается по порядку `config.SOURCES`, первым идёт
hh, поэтому теряется копия на второстепенном портале, куда автоотклик всё равно не ходит.

Дедуп **только межпортальный**: если один портал сам отдал вакансию дважды (hh
переопубликовывает объявления), обе записи остаются — это его история публикаций,
её описывает `republish_gap`.

Наблюдаемость: строка `Дедуп между порталами: снято N копий (talanto: …, hirify: …)` в логе
сбора. Замер на текущем кеше: снято 4507 из 87 118 (5.2 %) — talanto 4465, hirify 42,
hh не тронут.

## Сеть

**`net/http.py`** — единственный примитив `fetch_bytes(url, *, headers, proxy, max_time)`.
Бэкенд по `config.HTTP_BACKEND`: `curl` (дефолт) или `httpx` (пул keep-alive, экспериментальный).

Любое исключение, не-200 или пустой ответ -> `None`. Ретраи здесь **не делаются** — у HH и
hirify разные политики, каждый ретраит сам.

Проксированный запрос под httpx всё равно идёт через curl: пул не умеет ротацию IP
(`net/http.py::fetch_bytes`).

**`net/proxy.py`** — `proxie.txt` / `proxy.txt` в корне. Формат: URL как есть, либо
`host:port` -> `socks5://`, либо `host:port:user:pass` с `quote()`-экранированием.
`HH_DISABLE_PROXIES=1` отключает. `mask_proxy()` прячет креды в логах.

**`net/rates.py`** — курсы валют `open.er-api.com` (без ключа), кеш `data/fx_rates.json`,
TTL 24 ч. Каскад фолбэков: свежий кеш -> фетч -> **старый кеш даже протухший** ->
хардкод `_FALLBACK`. Лента не должна падать из-за FX.

Алиасы валют: `RUR->RUB`, `BYR->BYN`, `USDT->USD`. Пустая валюта трактуется как RUB
(HH по умолчанию рублёвый).

## Инкрементальный кеш описаний

Самый дорогой этап — карточки, поэтому описание переиспользуется, пока вакансия в выдаче
и её `sig` не менялся.

`cache_hit_usable(hit, cur_sig)` (`storage/files.py::cache_hit_usable`) требует три условия: sig совпал,
описание непустое, возраст < `DESC_CACHE_MAX_AGE_DAYS` (14).

Третье условие — предохранитель от **тихой правки вакансии без смены сигнала**. `0` отключает
ограничение по времени (чистый signal-based режим).

`load_desc_cache()` берёт только записи с `_enriched` **и** непустым описанием: tldr-заглушки
не должны блокировать будущую дозагрузку.

## Санити-гейт перезаписи

Главная защита данных. Живёт в `hh.py::_degraded_source`, пороги — `config.py::COLLECT_MIN_RATIO`.

```python
def _degraded_source(by_src, prior_by_src):
    for src, prev_n in prior_by_src.items():
        if prev_n >= COLLECT_SANITY_MIN and by_src.get(src, 0) < prev_n * COLLECT_MIN_RATIO:
            return src
    return None
```

Смысл: транзиентный блок источника на этапе поиска даёт резко меньший срез. Если источник,
дававший в прошлый раз >= 500 записей, просел ниже 50 % — сбор считается сбойным,
`repo.save()` **не вызывается**, возвращается старый кеш.

Порог значимости (`COLLECT_SANITY_MIN`) отсекает шум на мелких источниках, где падение
с 3 до 1 записи ничего не значит.

**Три уровня защиты в `collect()`:**

1. `cache_valid()` -> вообще не собираем (моложе `CACHE_TTL_HOURS`)
2. пустой результат -> кеш не трогаем (`hh.py::collect`)
3. `_degraded_source` -> кеш не трогаем (`hh.py::collect`)

Обход — `--force`. `cron/cron_collect.bat` запускается **без него** намеренно: для работы без
присмотра эту защиту снимать нельзя, один сбойный прогон уничтожил бы данные.

## Крайние случаи

- **Пустая первая страница hirify** -> warning + `[]`, не падение.
- **Пустой ответ на карточку HH** -> `return` без записи: ранее добытое описание не затирается.
- **Неизвестный источник в `SOURCES`** -> warning + пропуск.
- **Битый `cache_meta.json`** -> пересбор с нуля.
- **`cache_valid` учитывает состав** городов, запросов и `SOURCES`: правка `SEARCH_QUERIES`
  инвалидирует кеш, даже если он свежий по времени.

## Проверка

```
python hh.py collect            # уважает кеш и санити-гейт
python hh.py collect --force    # обход обеих защит — только руками
python hh.py enrich --only-empty
```

Ожидаемо в логе: `Всего уникальных: N вакансий  (hh: X, hirify: Y, talanto: Z, …)` — по
счётчику на каждый источник из `SOURCES`, всего девять, — и путь до
`data/vacancies_raw.json`. Если вместо этого `Источник hh: 300 << 16000 (< 50%)` — гейт
сработал, кеш цел, надо разбираться с блокировкой, а не запускать `--force` рефлекторно.
