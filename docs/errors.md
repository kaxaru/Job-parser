# Ошибки и отказоустойчивость

Система работает без присмотра по расписанию и ходит в чужие сервисы, которые её не ждут.
Отказ здесь — норма, а не исключение.

## Принцип

**Fail fast на своих ошибках, graceful degradation на чужих.**

Дрейф конфига, несовпадение констант, нарушенный инвариант — падаем сразу и громко.
Недоступная сеть, блокировка, битый ответ портала — деградируем и продолжаем.

Разница практическая: свою ошибку надо чинить, и тихая деградация её прячет. Чужую починить
нельзя, и падение из-за неё стоит дороже, чем пропуск одной вакансии.

## Fail fast

- **`Role.from_label` бросает `ValueError`** при неизвестном ярлыке. `_ROLE_RX` резолвит все
  ключи `ROLE_PATTERNS` **на импорте** `parsing.py` — опечатка в конфиге роняет процесс
  сразу, а не через час неправильной классификации.
- **`FreshnessClass.from_code` бросает** — тот же контракт для наших кодов.
- **Неудачный автовход** -> `SystemExit` с подсказкой «запусти `--login`». Продолжать
  бессмысленно: без сессии все отклики уйдут в `SKIP`.
- **Занятый lock** -> `SystemExit` в крон-прогоне. Второй Chromium на persistent-профиль
  сломал бы профиль.

## Graceful degradation

- **Источник упал** -> warning, пустой список, остальные порталы собираются
  (`hh.py::collect`)
- **HTTP не-200 / пустой ответ** -> `None`, ретраи у вызывающего
- **Все `chat.*`** -> пустое значение (`set()`, `{}`, `False`, `[]`)
- **LLM для письма упал** -> фолбэк на шаблон, отклик всё равно уходит
- **FX-API недоступен** -> старый кеш, даже протухший, дальше хардкод-фолбэк
- **Postgres недоступен** -> 503 только на `/api/search`, лента работает
- **esbuild отсутствует** -> warning, старый бандл остаётся рабочим
- **Битый JSON состояния** -> дефолт + warning

## Защита данных

Три уровня в `collect()`, любой блокирует перезапись кеша:

1. `cache_valid()` — данные свежие, не собираем вовсе
2. пустой результат — кеш не трогаем
3. `_degraded_source` — просадка >50 % при прошлом объёме >=500 -> кеш не трогаем

Плюс атомарная запись везде: читатель видит либо старый файл целиком, либо новый.

## Зависания

Отдельный класс отказов, потому что обычные таймауты против него не работают.

**Корневая причина** (подтверждена стеком 19.07): `page.wait_for_selector(timeout=20_000)`
простоял 50 минут. Таймауты Playwright исполняет node-драйвер; когда связка драйвер/CDP
клинит, Python блокируется в `_sync()` на трубе навсегда.

**Три эшелона:**

1. Playwright-таймауты 6–20 с — пока драйвер жив
2. `ApplyWorker.RESULT_TIMEOUT = 600 с` — HTTP-поток не ждёт вечно; `_drain("error")`
   в `finally` гарантирует, что `done` выставится даже при краше потока
3. Watchdog: 40 мин -> дамп стеков в stderr (диагностика, прогон продолжается);
   50 мин -> `lock.release_if_mine()`, затем `taskkill /F /T /PID <свой pid>`, фолбэк
   `os._exit(1)`. Lock отдаётся ДО выстрела: `taskkill /T` снимает и сам процесс, поэтому
   `finally` в `_single_instance` не наступает

**Почему не `ExecutionTimeLimit` планировщика.** Он снимает только `.bat`; python, node
и chromium осиротевают и продолжают держать профиль и lock — 19.07 после «завершения»
задачи жило 10 процессов. 50 минут watchdog'а < 60 минут лимита задачи, чтобы сработать
первым.

## Восстановление после kill

Watchdog убивает прогон в произвольной точке. Последствия смягчены двумя решениями:

**Marks, квота и журнал пишутся поштучно, сразу после каждого отклика**
(`autoclick.py::_apply_batch`). 18.07 они писались в конце батча — прогон умер в середине,
21 реальный отклик ушёл работодателям, а система о них не знала и предлагала те же вакансии
снова.

**`sync_statuses` восстанавливает журнал из чатов задним числом**, с реальными датами.
Работает без браузера и без lock, поэтому доступен даже когда браузерный путь сломан.
Подхватывает и отклики, сделанные руками на hh.ru — любой отклик создаёт чат.

**Осиротевший lock.** Два рубежа, и оба нужны:

1. **Прогон отдаёт lock сам** перед сносом дерева (`lock.py::release_if_mine`) — снимает
   только СВОЙ файл, чужой не трогает. Это единственная защита от reuse pid: файла нет —
   спорить о живости не о чем.
2. **Следующий инстанс снимает по мёртвому pid** (`lock.py::_pid_alive`) — на случай, когда
   отдать не успели (`os._exit`, снос извне, отключение питания).

Осознанная цена первого рубежа: под-секундное окно между отдачей lock и смертью Chromium,
в которое ждущий инстанс теоретически может влезть со вторым браузером на профиль. Принято:
вероятность мала (нужно попасть в доли секунды 60-секундного цикла ретраев), а альтернатива —
файл, переживающий прогон, — уже стоила 3 часов простоя откликов.

## Известные ошибки и их фиксы

Каталог реальных инцидентов — он объясняет, почему код выглядит именно так.

- **Мутация сущности через `salary_rub`** — `Analyzer` писал в общие объекты `Vacancy`.
  Фикс: пара `(Vacancy, rub)`, поле убрано из сущности.
- **`ExecutionTimeLimit` не убивал дерево** -> watchdog с `taskkill /T`.
- **`PermissionError [WinError 32]` при ротации** — параллельные процессы делили один
  лог-файл. Фикс: файл на процесс + `enqueue=True`.
- **Ложный отчёт «0 откликов»** — грепали `"Отклик:"` после смены формата на
  `"Отклик (сегодня N):"`.
- **Отклики не помечались при обрыве** — запись в конце батча. Фикс: поштучно.
- **21 опросник из 56 кандидатов** блокировал очередь -> `APPLY_SKIP_FORMS` + форм-очередь.
- **46 из 93 чатов терялись в ленте** — оверлей чатов шёл до `applyJournal`, который
  создаёт карточки-призраки. Фикс: порядок.
- **Кортеж вместо CSS-строки** в селекторе submit перебирался посимвольно, `locator('a')`
  кликал cookie-ссылку -> лавина вкладок.
- **Расклейщик листовок получал тег Android** — из клаузы «нужен смартфон на iOS/Android».
  Фикс: `_strip_device_req`.
- **«Да, есть опыт: Python»** на вопрос про автоматизацию тестирования ML-сервисов.
  Фикс: `_residual`.
- **Статусы стояли неделями** — синк вставал в очередь за откликами. Фикс: HTTP-only,
  без lock.
- **Письмо в анкете молча не вписывалось** — textarea письма нет в DOM, пока не кликнут
  тогл «Добавить» (`forms._LETTER_TOGGLE`). Фикс: `_fill_cover` сперва раскрывает тогл.
- **Отклик ушёл, но прогон счёл «не отправлено»** — HH показывает «Вы откликнулись» с
  лагом > 2с; учёт разъехался (applied на HH, но в форм-очереди). Фикс:
  `forms._wait_submitted` поллит до ~12с; при «НЕ ПОДТВЕРЖДЁН» проверять карточку руками.
- **Автоотклики стояли 3 часа после watchdog-убийства** (25.07). Два дефекта подряд:
  watchdog расстрелял своё дерево, `finally` не наступил -> lock остался с pid 26652; а
  `_pid_alive` считала «хендл открылся = жив», хотя `OpenProcess` УСПЕВАЕТ на убитом
  процессе, пока чужой хендл держит его объект (в списке процессов его уже нет,
  `GetExitCodeProcess` = 1, не 259). Крон-слоты выходили с «lock занят (pid=26652)» до
  истечения `LOCK_TTL`. Фикс: `release_if_mine()` перед `taskkill` + проверка кода выхода
  в `_pid_alive`.
- **Отклики на «Продюсер AI-видео» и «Инженер-испытатель»** — язык из ОПИСАНИЯ легитимизировал
  не-IT тайтл: у продюсера открывал креатив-гейт, у испытателя давал DEVELOPER-фолбэк. Фикс:
  креатив-гейт смотрит язык только в тайтле; «испытател(?!ьн)» — в `_HARD_NON_IT`.

## Что логируется

- `INFO` — прогресс: пул кандидатов, отклик, объёмы сбора
- `WARNING` — деградация: источник упал, кеш битый, esbuild не найден
- `ERROR` — санити-гейт сработал, watchdog убил прогон, автовход не удался
- `SUCCESS` — сбор завершён, отчёты записаны

Секреты в логах не появляются: `mask_proxy()` прячет креды, пароль читается из env и
никуда не печатается.
