## Данные / корректность (важное)

### ✅ 1. Часовой пояс applied_log — вероятный сдвиг на час

`funnel.py::_parse_ts` трактует наивные метки журнала как UTC+3 (`_MSK`), но кроновый
`log_applied` пишет `now()` локальной машины — а машина в самарской зоне **UTC+4**.
Латентность отказа занижается на час: реальные «65 мин» падают в бакет `<=1ч`, быстрые
отказы могут уйти в отрицательные и выпасть из `measured` (гвард их отбрасывает).

**Фикс:** локальный оффсет `datetime.now().astimezone().tzinfo` вместо хардкода `_MSK`.

### ✅ 2. Ложные отказы от classify

`funnel.py::compute_funnel`: `is_reject = st in _DISCARD or rej_ts is not None` — чатовое
reject-сообщение засчитывается отказом даже при статусе RESPONSE/INTERVIEW. У `classify`
известные ложные срабатывания («удалёнки, к сожалению, нет» в живом вопросе — см.
комментарий в `chat_class.py::find_contacts`). Отсюда 579 отказов при 556 DISCARD:
~23 чата, видимо, посчитаны по проходной фразе.

**Фикс:** чат-отказ учитывать только при подтверждающем статусе, либо вынести
«отказ по чату без статуса» отдельным срезом.

### ✅ 3. Двойной счёт invited + rejected

Вакансия со статусом INTERVIEW и reject-сообщением в чате инкрементит **и** `invited`,
**и** `rejected` — этажи воронки не взаимоисключающие,
`applied != invited + rejected + no_response`.

**Фикс:** приоритезировать исход (один этаж на вакансию) или явно задокументировать
пересечение в `docs/chat.md`.

### ✅ 4. Синк перезаписывает кеш «дырявым» результатом

`sync_statuses` сохраняет `save_statuses`/`save_chat_messages` файлом целиком из текущего
прогона. Если `chat_data` на один чат вернул `{}` (suppress проглотил сетевую ошибку) —
ранее известные статус и переписка этого чата **стираются**. То же с `limit`:
`chats[:limit]` в инкременте выкинет из файла всё за пределами лимита.

**Фикс:** merge поверх кешевой копии (начинать `msgs_out`/`statuses` с кеша), а не replace.

### ✅ 5. Пустой кеш замораживается навсегда

`autoclick.py::_sync_from_cache` не проверяет содержимое кешевой записи: терминальный чат
с пустым `messages` (артефакт старого неудачного фетча) больше никогда не перекачается —
скип по терминальности + старой метке вечен.

**Фикс:** скипать только если `cached_msgs[vid]["messages"]` непуст.

## Согласованность (среднее)

### ✅ 6. Словарь статусов размазан по трём местам

`funnel.py::_DISCARD` (3 кода) vs `autoclick.py::_TERMINAL_STATES` (`DISCARD`, `HIRED`)
vs `chat.py::STATE_LABELS`. Если HH шлёт `DISCARD_BY_EMPLOYER`, инкремент его не скипает
(потеря экономии), а воронка считает отказом — тихое расхождение.

**Фикс:** один источник правды в `chat`-модуле (наборы terminal/invited/discard).

### ✅ 7. Дубли id в журнале — берётся последний ts

`funnel.py::compute_funnel`: `{r["id"]: r for r in applied_log()}` перезапишет ранний
отклик поздним дублем. JS-лента (`marks.js::applyJournal`) сознательно берёт **самый
ранний** ts — он и есть реальный момент отклика, нужный латентности.

**Фикс:** брать минимальный ts на id, как в JS.

### ✅ 8. Два разных ранжирования + нечестный топ на малых n

CSV (`funnel.py`) сортирует по `auto_reject_rate`, график
(`charts.py::chart_company_funnel`) — по `(le_1h, rejected)`. Плюс `auto_reject_rate`
со знаменателем `rejected` (включая неизмеренные) и без порога по n: компания с 1/1
получает 100 % и топ-1.

**Фикс:** одно ранжирование; порог >=3 отказов или Wilson lower bound; знаменатель —
`measured`.

### ✅ 9. «(вне выдачи)» — 44 % откликов без работодателя

`employer_of` строится из текущей выдачи репозитория; для вакансий, выпавших из выдачи,
работодатель потерян навсегда.

**Фикс (на будущее):** писать `employer` в `applied_log` в момент отклика
(`store.log_applied`) — воронка по компаниям станет полной для новых данных.

## Мелочи

### ✅ 10. `pages=120` — снова магическое число

Потолок уже стрелял один раз (30 -> резало на 600). Можно выводить из
`len(applied_ids()) / 20 + запас` — самомасштабируется.

### ✅ 11. Оверлей — one-shot

`main.js::initOverlay` отрабатывает раз при загрузке; вкладка, висящая день, снова
показывает устаревшие чип/бейджи до F5. Периодический re-poll (раз в ~5 мин) закрыл бы это.

### ✅ 12. Формы-призраки не подсвечиваются

Цикл форм в `initOverlay` идёт **до** `applyJournal`, который синтезирует карточки для
выпавших из выдачи. Для чатов это уже чинили (инцидент «46 из 93») — формы наступают
на те же грабли: 52 в очереди vs 51 подсвеченных.

**Фикс:** перенести цикл форм после `applyJournal`.

### ✅ 13. `no_response` — неточное имя

Туда попадают и чаты с вопросом работодателя, ждущие НАШЕГО ответа — это не «молчат».
Точнее `no_outcome`.

### ✅ 14. Стиль

- `import csv` внутри `funnel.py::write_funnel_csv` — в проекте импорты сверху
- `path` в `write_funnel_csv` без типа `Path`
- `if st:` в скип-ветке `sync_statuses` мёртвый — терминальность уже гарантирует статус
- давность в чат-бейдже (`view.js`) есть только у `needs_reply`; у отказов и 📮 её нет,
  хотя тот же `ts` доступен
