# Лента и дашборд

**Слой:** `hrwork/presentation/views/`, `src/feed/*.js`, `src/dashboard.js`, `templates/*.j2`.

## Лента — назначение

Просмотр 40k+ вакансий в браузере с фильтрами, отметками и откликом в один клик.
Работает и через локальный сервер, и напрямую из `file://` (без сервера — без отметок
на диске и без отклика).

## Сборка (`views/feed.py`)

`build_feed()` читает репозиторий + статусы + форм-очередь + кеш свипа форм и пишет пять
артефактов в `data/`. Из кеша свипа (`store.form_cache`, `FormSweepStatus.is_dead`) карточка
получает `form_dead`: свип не нашёл полей -> вакансия, скорее всего, снята с публикации ->
серый класс `st-dead` + бейдж «⌛ не актуальна» (`view.js::statusBadge`). Помимо этого
карточка несёт бейдж свежести (`view.js::freshBadge`): возраст в днях от создания + класс
`fresh`/`recent`/`ghost`/`unknown` (иконка 🔥/👻), а также чип портала-источника
(hh/hirify/talanto). Пять артефактов:

- **`feed.html`** — лёгкий каркас с фильтрами
- **`feed.css`** — Jinja из `templates/feed.css.j2` с палитрой из `config`
- **`feed.js`** — бандл ES-модулей `src/feed/main.js` через **esbuild**
  (`--bundle --format=iife --target=es2020`). esbuild не найден -> warning, старый бандл
  остаётся на месте
- **`feed-data.js`** — `VACANCIES` без описаний (~8 % веса) + мост констант
- **`feed-desc.js`** — `window.__DESC = {id: html}` (~92 % веса, ~112 МБ), грузится **лениво**

Разделение data/desc — главное решение по производительности: без него старт ленты тянул бы
130 МБ.

### Мост Python -> JS

В `feed-data.js` инжектятся `SAL_MAX`, `SAVED_MARKS`, `FX_RATES`, `FX_ALIAS`,
`STATE_LABELS_PY`, `RESUME_CORE_PY`, `RESUME_EXPS_PY`, `MARK_VALUES_PY`, `CHAT_FROZEN_PY`.

Это не удобство, а защита от расхождения: подписи статусов, профиль резюме, словарь пометок
и **коды тупиковых чатов** (`chat_class.py::FROZEN_KINDS`) определены в Python, JS их получает,
а не дублирует. `CHAT_FROZEN_PY` появился, когда выяснилось, что код `'ack'` захардкожен
в трёх местах ленты (бейдж, фильтр «Личные», счётчик) — добавление второго фриз-вида
пришлось бы вносить в каждое.

**Цвет чат-бейджа** (`view.js::statusBadge`) = кто написал, кроме двух тупиков:
`bot_interview` — жёлтый `#E8C11C` с тёмным текстом (уводит в чужой мессенджер),
`ack` — ледяной `#5b8fb0`, человек — `#D64550`, бот — `#7B8794`, рассылка — `#4C9BD1`.
Оба фриза не дают эмодзи-автора и не попадают в «👤 Личные».

### Раскладка и токены (27.07)

**Липкой осталась только полоса управления** (`.filter-toolbar`, ~48px): поиск, счётчик
выдачи, кнопка «Фильтры» и сброс. Панель с группами (`#filter-bar`) — обычный блок, который
сворачивается; состояние живёт в `localStorage['feed.filtersOpen']`. Причина замерена на
живой странице: липкий бар с фильтрами занимал 398px при окне 1000px (**40% экрана
постоянно**, при прокрутке он оставался на месте), а на ширине 900px — 691px из 900, то есть
**77%**, и до карточек надо было доскроллить. На кнопке висит счётчик активных групп
(`model.js::countActiveFilters`) — свёрнутая панель не должна скрывать, что выдача урезана.

**Токены темы** — `:root` в `feed.css.j2`: палитра из Python плюс приглушённые тона,
подобранные по контрасту (`--muted` 4.6:1 на карточке, `--muted-on-bg` 4.5:1 на фоне).
Раньше по файлу была россыпь из девяти хардкод-серых, и три места не проходили AA:
«ничего не найдено» давало 1.94:1, подсказки — 2.93:1. Подложки бейджей затемнены до 4.5:1
(белый текст 11px bold требует именно этого), `tagInk` осветляет цвет технологии до 4.5:1
как ТЕКСТА на карточке.

**`color-scheme: dark`** на корне — иначе Chrome рисует нативные списки (выпадающий
`datalist` города), скроллбары и календари в светлой теме поверх тёмной страницы. Раньше
свойство стояло только на `.date-input`, то есть проблему лечили точечно.

**Доступность.** Карточка получила `tabindex`/`role`/`aria-label` и реакцию на Enter и
пробел — до этого `div` с обработчиком клика не открывался с клавиатуры вовсе. Модалка —
`role="dialog"`, фокус уходит на «закрыть», Tab заперт внутри, после закрытия возвращается на
карточку. Есть общий `:focus-visible` и `prefers-reduced-motion`.

**Первая отрисовка.** `feed-data.js` весит ~50 МБ, и пока браузер его парсит, сетка пуста.
Заглушка — чистый CSS: `.cards-grid:empty::after`, снимается сама при вставке первой карточки.

**Тон рамки карточки** — `model.js::cardTone`, отдельно от `cardColor`. Приоритет:
отказ HH (`st-rejected`, красная) -> приглашение (`st-applied`, зелёная) ->
бот-интервью (`st-botiv`, жёлтая) -> ручная пометка. Логика в том, что жёлтый — это
**предупреждение**, а отказ и приглашение — реальный исход, и он сильнее: отказ на
бот-интервью красит карточку красной, статус остаётся «Отказ».

`applyCardStatus(card, st, tone)` разводит две роли, раньше склеенные в одну: `tone` красит
рамку, `st` подсвечивает кнопку ✓/✕. Без этого «✓ Отклик» на бот-интервью возвращал
карточке зелёный цвет.

### Санитизация описаний

`_DescSanitizer(HTMLParser)` + `sanitize_desc` (`feed.py::_DescSanitizer`, `::sanitize_desc`) — **единственное место,
где чужой HTML попадает в `innerHTML` без экранирования**.

Allowlist тегов: `p`, `br`, `ul`, `ol`, `li`, `strong`, `em`, `b`, `i`. Все атрибуты
срезаются полностью. `script` и `style` выбрасываются вместе с содержимым.

Чистка происходит один раз на сборке, поэтому защищает оба режима — и `serve`, и `file://`.
Покрыто `tests/backend/presentation/test_sanitize.py`.

## Фронт — MVVM

**`store.js`** — минимальный ViewModel: `createStore(initial)` -> `{get, update, subscribe}`.
Поток однонаправленный: событие -> `update` -> notify -> `render`.

`update(patch, notify=false)` для точечных изменений (тоггл статуса одной карточки), чтобы
не перерисовывать 10k карточек ради одного бейджа.

**`model.js`** — чистая логика, без DOM и IO. Здесь `filterVacancies` — **единственная**
точка фильтрации и сортировки.

Фильтры: поиск по токенам (name + employer), `resumeOnly`, роли, `showNonIt`, языки, опыт,
диапазон зарплаты **с конверсией валют**, источник, город, формат, статус, чат-фильтр,
календарный диапазон.

**Город — список с поиском внутри** (`#city-inp` + `<datalist>`, было `<select>` на ~1800
опций). `model.js::cityMatches` разводит два режима: значение выбрано из списка
(`cityExact`, его ставит `main.js` по `CITY_SET`) -> строгое равенство; набрано вручную ->
подстрока, поэтому «сан» находит Санкт-Петербург. Без этого разделения подстрока на точном
выборе тянула бы лишнее — «Москва» вместе с «Московский». Ввод дебаунсится на 150 мс, как
общий поиск: ре-фильтр идёт по всей выдаче.

Режим `mine` («Мои отклики») — самостоятельный вид: только свои отклики за период, прочие
чипы игнорируются, сортировка по дате отклика. Гост-вакансии отсеиваются в режимах совпадения.

Сортировка составная: совпадение с резюме — основной ключ, зарплата — вторичный;
`date_new` / `date_old` — самостоятельный ключ. Пустые значения всегда в конце.

Валюты: `resolveCur` / `convert` / `fmtSal` через базу USD, курсы приходят из Python.

**Пилюли-чекбоксы** (языки / роли / опыт) скрывают нативный `input` и красят `<label>`.
Правило в CSS привязано к МЕСТУ — `.lang-grid input[type=checkbox]`, а не к списку классов:
пока перечислялся только `.lang-cb`, в группе «Роль» (класс `role-cb`) торчали стандартные
чекбоксы и пилюля не подсвечивалась при выборе. Классы в разметке остаются — по ним `main.js`
различает группы (`.lang-cb:not(.exp-cb)` = языки), склеить их в один нельзя. Чекбокс уводится
из потока (`position:absolute; opacity:0`), а не `display:none`, иначе теряется фокус и
`:focus-visible` не может подсветить пилюлю с клавиатуры.

**`view.js`** — рендер DOM. Кэш разметки `_cardCache` по id (данные иммутабельны),
инвалидация через `bustCard`. Статус карточки — CSS-класс, навешивается **после** вставки,
чтобы не протухал кэш.

Рендер **инкрементальный**: `CHUNK = 80` + `IntersectionObserver` со сторожем и
`rootMargin: 800px`. Это и есть ответ на 34k карточек в DOM.

**`marks.js`** — граница сайд-эффектов, состоянием не владеет. `pushServer` бросает и на
HTTP-статусе тоже: иначе 500 от сервера давал бы пользователю ложное «✓ сохранено».

`loadDescriptions` грузит `feed-desc.js` через `<script>`, а не `fetch` — чтобы работало
из `file://`.

**`main.js`** — bootstrap: store на ~20 полей, подписка на render, привязка событий.
`persist()` пишет в localStorage мгновенно, на сервер — с debounce 400 мс.

### Живой оверлей

`initOverlay()` (`main.js::initOverlay`) параллельно тянет `/api/forms`, `/api/statuses`,
`/api/applied`, `/api/chats` и накладывает поверх статической ленты **без пересборки**.
Повторяется каждые 5 минут (`setInterval`): вкладка живёт открытой весь день, one-shot
оверлей устаревал до F5. Все ветки идемпотентны — инжекты фильтров при повторе только
освежают счётчики.

`/api/forms` отдаёт очередь с признаком `dead` (протухшесть из кеша свипа) — оверлей
ставит и `needs_form`, и `form_dead`, затем `refreshFormsChip` пересчитывает чип
«📝 Формы (живые+N⌛)» по факту. Запечённое при сборке число считается ПО ВЫДАЧЕ
(живые+протухшие, тот же формат), а не `len(forms)`: очередь содержит и вакансии,
выпавшие из выдачи, и без живого пересчёта чип отставал от карточек (крон дописывает
формы весь день, лента статична).

**Порядок обработки критичен:** `applyJournal` идёт **первым** — он синтезирует
карточки-призраки для вакансий, выпавших из выдачи после пересбора; формы, статусы и
чаты обрабатываются после и потому находят призраков. На этом уже дважды спотыкались:
чаты (терялась половина — 46 из 93), затем формы (52 в очереди vs 51 подсвеченных).

### Отметки и журнал

**Marks** — ручные отметки `{id: applied|rejected}`, источник правды `data/marks.json`,
живут отдельно от данных и переживают пересбор.

**Journal** — `applied_log.jsonl` через `/api/applied`; берётся **самый ранний** ts на
вакансию. Даёт бейдж «📮 дд.мм» и режим «Мои отклики».

## Дашборд

`views/dashboard.py` + `views/charts.py`, Plotly (`pio.to_html(include_plotlyjs=False)`).

Реестр `_CHARTS` — 14 вкладок: Города, Зарплата по языку, Зарплата по опыту, Пары языков,
Город × язык, Технологии по городам, Удалёнка, Python-стек, JS-стек, Свежесть/гост, Компании,
Все работодатели, Удалёнка: компании, Порталы.

Вкладка появляется, только если существует её CSV — дашборд не падает на неполных данных.

**Палитра диаграмм** (`charts.py`, константы `SEQ_SCALE` / `BAR_COLOR` / `AGE_SCALE`) —
три правила, и все три ломались на тёмной подложке:

- **Последовательная шкала растёт к светлому** (`reversescale=True`). У Plotly светлый конец
  идёт первым, поэтому без разворота максимум красился почти в чёрный и терялся, а хвост
  мелких значений светился ярче всех: на «Городах» Москва с 20307 была самой незаметной
  строкой, а Пермь с 669 — самой яркой.
- **Цвет не дублирует ранг.** Там, где величина уже закодирована длиной бара и сортировкой
  (города, пары языков, стек языка), заливка одна на серию; градиент по тому же числу —
  избыточное кодирование. Тон остаётся различающим признаком только между парными
  диаграммами (Python-стек против JS-стека).
- **Расходящаяся шкала = два тона и нейтральная середина**, не радуга. Возраст компаний был
  на `RdYlBu` с жёлтой серединой; теперь тёплый -> серый -> холодный, в той же метафоре, что
  `model.js::ageColor` в ленте.

**Срезы по источникам:** при более чем одном портале `reporter.run_reports` прогоняется
дополнительно в `reports/by_source/<src>/`, фигуры рендерятся под каждый источник.
Вкладка «Порталы» — только в общем срезе.

`src/dashboard.js` копируется как есть (`shutil.copy`), без Jinja и esbuild. Он переключает
вкладку × источник и шлёт `resize`, чтобы Plotly перерисовался под видимую панель.

### Общий хелпер стековых баров

`_stacked_pct_bars` (`charts.py::_stacked_pct_bars`) — 100 %-нормированный (`barnorm="percent"`)
горизонтальный стек, вынесенный из трёх копий (companies_sizes / freshness / remote).

Каталог CSV передаётся **явным параметром `base`** в каждую `chart_*`. Раньше был
module-global `_BASE` + `set_reports_dir` — гонка при конкурентной сборке по-портальных
срезов.

## Отчёты

`views/reporter.py` — CSV и консольные отчёты. `ReportWriter` — инстанс на прогон,
реестр `_REPORTS` из 12 функций задаёт порядок.

`cleanup()` удаляет CSV, не записанные в этом прогоне, но **только** в `REPORTS_DIR` —
иначе снесло бы по-портальные срезы.

Артефакты: `data/reports/01_cities.csv` … `12_sources.csv`.

## Крайние случаи

- **esbuild отсутствует** -> warning, старый `feed.js` остаётся рабочим
- **CSV отчёта нет** -> вкладка дашборда просто не появляется
- **`file://` режим** -> отметки только в localStorage, кнопка отклика скрыта
- **Вакансия выпала из выдачи, но по ней есть отклик** -> карточка-призрак из журнала
- **500 от `/api/marks`** -> `pushServer` бросает, «✓» не показывается
