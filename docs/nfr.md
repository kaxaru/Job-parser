# Нефункциональные требования

Требования к системе, не выражаемые через «что она делает». Каждое — с числом и способом
проверки, иначе это пожелание, а не требование.

## Производительность

**Сбор** — полный цикл (3 источника: hh + hirify + talanto, 34 города, ~35 запросов,
~90k уникальных вакансий) укладывается в 2 часа. Лимит крон-задачи `hh_collect` — по этому.

Достигается: параллельные источники, поиск по городам конкурентно, отсев не-IT по тайтлу
**до** enrich, инкрементальный кеш описаний.

**Детекция техов** — ~55 regex на 46k вакансий за секунды, не минуты. Подстрочный пресин
дал 137 c -> 8 c при нулевом расхождении результата (`test_prescreen.py`).

**Лента** — открывается за секунды при 40k+ вакансий. Достигается разделением
`feed-data.js` (~21 МБ, грузится сразу) и `feed-desc.js` (~112 МБ, лениво) плюс
инкрементальным рендером чанками по 80 с `IntersectionObserver`.

**Статика** — gzip + ETag с кэшем по `(mtime, size)`. Без кэша каждый запрос пере-сжимал бы
112 МБ.

**Отклик** — 20 штук за прогон при паузах 4–9 с укладывается в час (лимит задачи `hh_apply`).

## Надёжность

**Данные не теряются при сбое источника** — три уровня защиты перезаписи кеша.
Проверяется `test_collect_guard.py`.

**Прогон не висит дольше 50 минут** — watchdog с `taskkill /F /T`. Верхняя граница выбрана
меньше `ExecutionTimeLimit` задачи (60 мин), чтобы сработать первым.

**Отклик не теряется при обрыве** — marks, квота и журнал пишутся поштучно сразу;
`sync_statuses` восстанавливает журнал из чатов задним числом.

**Один писатель на файл** — single-instance lock для браузерного пути, `threading.Lock`
для marks, файл лога на процесс.

**Частичная запись невозможна** — атомарная запись через tmp + `os.replace` везде, кроме
append-only журнала.

## Корректность данных

**Не приписывать пользователю опыт, которого нет** — жёсткое требование, отсюда весь дизайн
`chat_answer.py`: нет факта -> нет ответа. Проверяется 13 тестами.

**Не показывать нерепрезентативную статистику** — медиана зарплаты требует минимум
5 наблюдений (`MIN_SAMPLE_SALARY`), ячейка город × язык — 3 (`MIN_SAMPLE_CITY_LANG`).
Ниже порога срез не показывается вовсе.

**Константы не расходятся молча** — тесты-стражи (`test_role.py`), fail-fast на импорте,
мост Python -> JS вместо дублирования.

## Совместимость

**Windows 11** — целевая и единственная проверенная платформа. Учтено: `taskkill` вместо
сигналов, `OpenProcess` для проверки живости pid, невозможность переименовать открытый файл
(лог на процесс), curl-подпроцессы вместо aiohttp (`WinError 64` через VPN).

**Терминал cp1251** — в выводе ASCII-стрелки `->`, эмодзи в именах экранируются.

**Лента работает из `file://`** — без сервера, с отметками в localStorage. Отсюда
`loadDescriptions` через `<script>`, а не `fetch`.

## Наблюдаемость

**Любой прогон объясняет себя в логе.** Не «ошибка», а что именно и с какими числами:
`Источник hh: 300 << 16000 (< 50%)`, `Отклик (сегодня 47): <название>`.

**Уровни осмысленные** — `INFO` прогресс, `WARNING` деградация, `ERROR` сработавшая защита.
Access-лог сервера заглушён до 4xx/5xx, иначе лента залила бы его сотнями строк.

**Секреты не логируются** — `mask_proxy`, пароль не печатается.

## Ограничения площадки

Не технические, а внешние — их нарушение стоит аккаунта.

- 200 откликов в сутки (`HH_DAILY_APPLY_CAP`)
- Поднятие резюме не чаще раза в 4 часа
- Паузы 4–9 с между откликами, 0.1–0.3 с между чат-запросами
- `User-Agent` реального браузера, отключённый automation-флаг

## Поддерживаемость

**Новый портал добавляется без правки оркестратора** — подкласс `Source` + имя в
`config.SOURCES`. Проверяется тем, что hirify добавлен именно так.

**Схема хранения инкапсулирована** — `_from_dict` / `_to_dict` в репозитории, единственное
место, знающее сырой формат. Подмена на Postgres не затронет потребителей.

**Доменное понятие = тип.** Примитив вместо VO считается дефектом проектирования на этапе
спеки, а не деталью реализации.

**Осознанные компромиссы задокументированы на месте** — комментарием в коде и разделом
в доке, чтобы следующий аудит их не «починил».

## Что сознательно не требуется

- **Масштабирование** — один пользователь, одна машина. Отсюда JSON вместо БД.
- **Высокая доступность** — пропущенный слот наверстается следующим.
- **Мультитенантность, RBAC, аудит-лог** — один пользователь.
- **Кроссплатформенность** — только Windows; Linux потребовал бы переписать процессное
  управление.
- **E2E-тесты** — единственный сквозной путь отправляет реальные отклики.
